# N138 · Sparse Table 与静态 RMQ —— 说人话详解

> 对应 notebook：`notebooks/16_advanced_structures/138_sparse_table_rmq.ipynb`

## 一、这章要解决什么问题？（问题描述）

这一章解决"区间最值查询（RMQ）"的静态版本：数组从头到尾不会变，但会问你很多次"下标 left 到 right 这段的最小值（或最大值）是多少"。线段树也能做，每次 O(log n)；稀疏表（Sparse Table）用空间换时间，预处理之后每次查询只要 O(1)——两次数组取值加一次 min/max。

一个具体到数字的例子（cell6 用的）：数组 `[4, 2, 5, 1, 7]`，查询 `query(0, 5)`（整个区间）返回 1。它是这么算的：区间长度 5，取不超过 5 的最大 2 的幂 4，用"从 0 开始长度 4 的块"和"从 1 开始长度 4 的块"盖住 `[0,5)`——两块分别是 `[4,2,5,1]`（最小 1）和 `[2,5,1,7]`（最小 1），中间 `[1,4)` 被重复盖了，但 min 对重复元素无所谓，min(1,1)=1，答案正确。cell6 打印的那行 `长度5由[0,4)与[1,5)两块覆盖： 1` 说的就是这个。

## 二、关键概念（定义）

- **RMQ（Range Minimum/Maximum Query，区间最值查询）**：给定区间问最小值或最大值，是最经典的区间问题之一。
- **稀疏表（Sparse Table）**：一个二维表 `table[k][i]`，存的是"从下标 i 开始、长度为 2^k 的一段"的最值。预处理把所有 2 的幂长度的块都算好，查询时拿两块拼起来。你要它是因为查询真的只有 O(1)。
- **log 表 / bit_length**：查询时需要知道"区间长度 L 对应多大的 2 的幂"，代码用 `(right-left).bit_length()-1` 现场算出 k，即 floor(log2(L))。比如 L=5，二进制 101 是 3 位，bit_length 是 3，k=2，块长 2^2=4。
- **幂等（idempotent）**：同一个元素被合并多次结果不变，min(min(x,x),x)=min(x,x)=x。min、max、gcd 都幂等，所以两块重叠不碍事；加法不幂等（x+x ≠ x），所以这套"允许重叠"的查询公式不能搬到求和上。
- **重叠块**：查询区间 `[left, right)` 被两块等长区间覆盖时，两块在中间可以叠一块。能重叠是 O(1) 查询的关键——不用把区间精确切成不重叠的小块。
- **静态（static）**：数组不发生任何更新。稀疏表一旦建好就不能改，改一个元素整张表作废，这是它换 O(1) 查询付出的代价。
- **单调队列（monotonic deque）**：解"固定长度滑窗最大值"的另一个工具，整体 O(n)。cell4 特别提醒：固定窗口一次性求最大值用单调队列更省，不要学了稀疏表就什么都用它。
- **gcd（最大公约数）也是幂等的**：cell0 知识点里把 min/max/gcd 并列，因为 gcd(gcd(x,x),x)=gcd(x,x)=x，同样可以走"两块重叠"的查询公式，一章学三个运算。
- **静态查询的量级直觉**：预处理 O(n log n)、单查 O(1) 的组合在"查询次数远大于元素个数"时最划算；反过来，只查一两次的场景连预处理都是浪费，直接 `min(a[l:r])` 暴力反而最快。
- **Disjoint Sparse Table**：拓展概念，块不重叠的稀疏表变体，能支持一般结合运算（包括不幂等的），本章只提名字不实现。

## 三、解决思路（一步步推导）

- **Step 1**：`table[0]` 就是原数组本身——"长度为 1 的块的最值"就是元素自己。
- **Step 2**：逐层倍增。`table[k][i]` 表示从 i 开始长度 2^k 的块，它恰好由"从 i 开始长度 2^(k-1) 的块"和"从 i+2^(k-1) 开始长度 2^(k-1) 的块"拼成，所以 `table[k][i] = combine(table[k-1][i], table[k-1][i+half])`。每层起点个数少一些，直到块长超过 n 为止。
- **Step 3（查询）**：对区间 `[left, right)`，算 k = floor(log2(right-left))，取"从 left 开始的长度 2^k 块"和"从 right-2^k 开始的长度 2^k 块"。两块拼起来一定盖满整个区间（也可能中间重叠），combine 一下就是答案。两个下标都不会越界：左块起点 left 合法（区间非空保证 left < n）；右块起点 right-width ≥ left ≥ 0（因为 width ≤ 区间长度），且它在第 k 行的合法起点范围内。
- **Step 4（正确性的关键直觉）**：为什么重叠没关系？因为 min/max 幂等，重复参与的元素不会改变结果。为什么不能用于求和？因为重叠部分的元素会被加两次。
- **Step 5（static_window_max）**：固定长度 k 的滑动窗口最大值 = 对每个窗口起点 i 查一次 `[i, i+k)` 的最大值，共 n-k+1 次 O(1) 查询。

**手算演示（cell6 建表，a = [4, 2, 5, 1, 7]）**：

| 块长 2^k | 各起点块最小值 | 说明 |
|---|---|---|
| 1（k=0） | [4, 2, 5, 1, 7] | 原数组 |
| 2（k=1） | [2, 2, 1, 1] | 例如起点 0：min(4,2)=2；起点 3：min(1,7)=1；只有 4 个起点（0..3） |
| 4（k=2） | [1, 1] | 起点 0：min(前 4 个)=1；起点 1：min(后 4 个)=1；块长 8 超过 n=5，建表到此为止 |

查询 `query(0, 5)`：长度 5 → k=2、块长 4 → 取 `table[2][0]=1`（盖住 `[0,4)`）和 `table[2][5-4]=table[2][1]=1`（盖住 `[1,5)`）→ min(1,1)=1。整个过程就是两次列表取值加一次 min，没有任何循环。

再演示一个"两块不同值"的查询，`query(1, 4)`（区间 `[2,5,1]`，正确答案 1）：长度 3 → bit_length(3)=2，k=1、块长 2 → 左块 `table[1][1]=2`（盖住 `[1,3)` 即 [2,5]），右块 `table[1][4-2]=table[1][2]=1`（盖住 `[2,4)` 即 [5,1]）→ min(2,1)=1。注意下标 2 的元素 5 被两块都盖到了，但 min 幂等，重复无害。

**手算演示（static_window_max，cell8 的标准用例）**：`nums=[1,3,-1,-3,5,3,6,7]`，k=3，窗口从左往右滑：

| 窗口起点 i | 窗口内容 `[i, i+3)` | 最大值 |
|---|---|---|
| 0 | [1, 3, -1] | 3 |
| 1 | [3, -1, -3] | 3 |
| 2 | [-1, -3, 5] | 5 |
| 3 | [-3, 5, 3] | 5 |
| 4 | [5, 3, 6] | 6 |
| 5 | [3, 6, 7] | 7 |

六个窗口各做一次 O(1) 的 RMQ 查询，拼起来正是断言里的 `[3,3,5,5,6,7]`。观察一个细节：滑动时窗口内容每次只换一个元素，但稀疏表完全没利用这个连续性（每个窗口独立两块查询）；单调队列正是利用"进一个出一个"的特性把总代价压到 O(n)，这是练习 2 要对比的点。

再核对一个具体窗口的内部计算：起点 2 的窗口 [-1,-3,5]，query(2,5)：长度 3 → k=1、块长 2 → 左块 table[1][2]、右块 table[1][3]，分别是 max(-1,-3)=-1 和 max(-3,5)=5 → max(-1,5)=5。下标 -3 所在位置被两块都盖到，重复无害，结果与手数一致。

至此三个演示（建表、单次查询、逐窗滑动的整表应用）把 cell6 和 cell8 的数据都过了一遍，你可以合上手算、直接预测 notebook 的输出，再运行对照——这正是 cell0 里"先读推导，再预测输出"的学习方式。

## 四、代码逐段讲解

cell3 有四块：基类 `_SparseTable`、两个子类、一个滑窗函数。

**基类构造函数 `__init__`**

```python
    def __init__(self,values,combine):
        self.n=len(values); self.combine=combine; self.table=[list(values)]; width=2
        while width<=self.n:
            half=width//2; old=self.table[-1]
            self.table.append([combine(old[i],old[i+half]) for i in range(self.n-width+1)]); width*=2
```

`self.table=[list(values)]` 把第 0 层设为原数组的拷贝（长度 1 的块）。`while width<=self.n` 从块长 2 开始逐层翻倍，块长超过 n 就停。每层 `old=self.table[-1]` 拿上一层的行，列表推导式对每个合法起点 i（共 `n-width+1` 个，保证 `i+half` 不越界）合并"上半块 old[i]"和"下半块 old[i+half]"。整个预处理每层 O(当前层起点数)，总共 O(n log n)。

**查询 `query`**

```python
    def query(self,left,right):
        if not 0<=left<right<=self.n: raise IndexError('nonempty half-open interval required')
        k=(right-left).bit_length()-1; width=1<<k
        return self.combine(self.table[k][left],self.table[k][right-width])
```

第一行挡非法区间：left、right 必须满足 `0<=left<right<=n`，注意这里是严格小于——空区间（left==right）被拒绝，因为"空区间的最小值"没有良定义（min 没有自然的单位元），报错信息 `nonempty half-open interval required` 也在明说这一点。`k=(right-left).bit_length()-1` 一行算出 floor(log2(L))：L=5 时 bit_length=3，k=2；`width=1<<k` 还原成块长 4（`1<<k` 是二进制左移，等于 2 的 k 次方）。最后返回两块的 combine：`table[k][left]` 是从左端起的块，`table[k][right-width]` 是顶到右端的块（起点 right-width 保证块恰好结束在 right）。对照第三节的表核对一次：query(1,4) 时 k=1、width=2，取 `table[1][1]=2` 和 `table[1][2]=1`，min 得 1，与手算一致。

**两个子类**

```python
class SparseTableMin(_SparseTable):
    def __init__(self,values): super().__init__(values,min)

class SparseTableMax(_SparseTable):
    def __init__(self,values): super().__init__(values,max)
```

它们只做一件事：把 combine 固定成 min 或 max 传给父类。基类名前带下划线表示"内部用"，外部请用这两个具体版本。

**滑窗最大值 `static_window_max`**

```python
def static_window_max(nums,k):
    if k<=0: raise ValueError('positive window length required')
    tree=SparseTableMax(nums)
    return [tree.query(i,i+k) for i in range(len(nums)-k+1)]
```

第一行挡非正窗口长度（k=0 或负数直接抛 ValueError，报错信息 `positive window length required` 把要求说得很直白）。然后建一张最大值表，对每个窗口起点 i（从 0 到 `len(nums)-k`，共 n-k+1 个）查 `[i, i+k)` 的最大值。变量名叫 tree 只是习惯叫法，它其实是表不是树。特别注意这个函数复用的是 `SparseTableMax` 而不是 min 版——窗口最大值当然要查最大，但这句废话背后有个正经提醒：基类把 combine 当参数，所以"同一个基类派生 min 版和 max 版"是零成本的，泛化已经替你付过钱了。

## 五、为什么是对的？复杂度是多少？（说人话）

为什么两块一定盖住区间：设区间长度 L，块长是 2^k，由 k 的取法知道 2^k ≤ L < 2^(k+1)，即 L < 2×2^k。左块从 left 起盖住前 2^k 个，右块结束在 right、往前盖住 2^k 个，两块合起来盖住 2×2^k > L 个位置，从两头往中间夹，中间不可能漏；至多多盖的部分就是重叠区。因为 min/max 是幂等的（一个元素算一遍和算两遍结果一样），重叠完全不改变 combine 的结果，所以答案正确。反过来，notebook 用一个测试专门钉死这一点：`a=[1,2,3]` 时 `sum(a[:2])+sum(a[1:])` 是 (1+2)+(2+3)=8，而真正的 `sum(a)` 是 6，中间的 2 被重复加了——求和不是幂等的，不能套这个公式。想支持一般结合运算，得换不相交分块或 Disjoint Sparse Table（拓展）。

复杂度：预处理共 log2(n) 层，每层起点数不超过 n，时间空间都是 O(n log n)。具体到数字，n = 10^5 时表大约是 17 层、每层最多十万个数，合计一百七十万个格子，内存几 MB，可接受。查询是 O(1)——两次下标加一次 min/max，一百万次查询也只是百万次基本操作，一瞬间。代价是数组静态：一旦更新某个元素，所有覆盖它的块全部失效，重建要 O(n log n)，所以动态场景请回上一章用线段树。另外 cell4 明确提醒：如果只是"固定窗口扫一遍求最大值"这种一次性任务，单调队列整体 O(n)、连预处理都不用，比稀疏表更合适。

三种"区间最值工具"的选型可以排个序，帮你建立直觉：

| 场景 | 首选 | 理由 |
|---|---|---|
| 数组不变、查询海量 | 稀疏表（本章） | 预处理一次，单查 O(1) |
| 边改边查 | 线段树（N136） | 更新查询都 O(log n) |
| 固定窗口滑一遍求最值 | 单调队列 | 整体 O(n)，无预处理 |
| 只要前缀和/计数 | 树状数组（N135） | 代码最短 |

拿本章小例子算笔账：n = 6 的 `[4,2,5,1,7]`，预处理只建了 3 层共 11 个格子，这在实际工程里当然不划算（暴力 min 反而最快）；稀疏表的价值要在"查询次数远大于 n"时才兑现，比如 n = 10^5、查询 10^6 次，稀疏表约 10^6 次基本操作就全部答完，暴力每次 O(n) 则要 10^11 次，差距是天壤之别。

## 六、测试用例在测什么

- `assert SparseTableMin([4,2,5,1]).query(0,4)==1`：正常值测试，全区间最小值是 1，验证建表和查询公式的基础正确性。区间长度 4 恰好是 2 的幂，两块完全相同（起点 0 和起点 0），是"整块命中"的形态。
- `assert static_window_max([1,3,-1,-3,5,3,6,7],3)==[3,3,5,5,6,7]`：这是 LeetCode 239 的标准用例，含负数（-1、-3）和多种窗口形态，验证滑窗封装逐窗正确。
- 中段双重循环（种子 138）：n 从 1 到 34，对每个长度随机出值域 [-9, 9] 的数组，然后枚举所有满足 `l<r` 的区间，断言 min 版和 max 版分别等于暴力 `min(a[l:r])`、`max(a[l:r])`。这是穷举式对拍——所有长度、所有位置、各种奇偶区间形状全测到，比随机抽样更全面。
- `assert static_window_max([1,2],3)==[]`：边界测试，窗口长度 3 超过数组长度 2，起点范围 `range(2-3+1)` 为空，应返回空列表而不是报错（注意它没触发 k<=0 的检查，测的是另一个边界）。
- `a=[1,2,3]; assert sum(a[:2])+sum(a[1:])!=sum(a)`：这条不是测实现，而是"文档式断言"——它用 8 ≠ 6 的事实证明重叠公式对求和会重复计入中间元素，把"为什么只限幂等运算"这个前提钉进测试里。手算一遍这行：`a[:2]` 是 [1,2] 和为 3，`a[1:]` 是 [2,3] 和为 5，两块相加 8；而 `sum(a)` 是 6，中间的 2 被数了两次。如果哪天你想把稀疏表改成支持求和，这条断言就是"此路不通"的警示牌。

中段穷举对拍还有一个隐藏作用：它同时测了"两块完全重合"（区间长度恰为 2 的幂，如 query(0,4)）和"两块错开"（长度非 2 的幂，如 query(1,4)）两种形态，还测了长度 1 的最小区间（此时 k=0，左右两块是同一片叶子）。这些形态如果只靠手写用例，很容易漏掉一两种。

## 七、练习思路提示

**练习 1：构造用重叠两块求 sum 的错误反例。** 提示：反例非常好找——只要查询区间长度不是 2 的幂，两块就会重叠，重叠部分被加两次。拿 `[1,2,3]` 查 `[0,3)` 手算：左块 [0,2) 的和是 3，右块 [1,3) 的和是 5，套重叠公式得 8，而正确答案是 6，中间的 2 被重复计入。再想一个极端例子：所有元素都是 1、区间长 3，公式得 4 而正确是 3。写报告时把"幂等 vs 不幂等"的对比说清楚，并提一句 Disjoint Sparse Table 为什么能救不幂等的运算（它的块不重叠）。

**练习 2：比较 RMQ 与单调队列解滑窗。** 提示：固定长度 k 的滑窗最大值有两种解法——稀疏表先 O(n log n) 预处理、每窗 O(1)；单调队列（双端队列维护递减候选）一遍扫完、每个元素最多进出队各一次、整体 O(n)。建议两个都实现，用 `static_window_max([1,3,-1,-3,5,3,6,7],3)` 的期望输出 `[3,3,5,5,6,7]` 对拍，然后从三个角度比较：预处理开销、单次查询与整体复杂度、代码量。结论方向：一次性滑窗任务选单调队列；窗口长度多变或区间随机查询多、且数组静态不变，稀疏表才划算。

## 八、对应 LeetCode 题目

- **239. Sliding Window Maximum（滑动窗口最大值）**：extension 题，`static_window_max` 就是它的一种解法（另一经典解是单调队列，见练习 2），练的是"静态 RMQ + 固定窗口"的组合。
- **1438. Longest Continuous Subarray With Absolute Diff Less Than or Equal to Limit（绝对差不超过限制的最长子数组）**：extension 题，用一张 min 表和一张 max 表（`SparseTableMin` + `SparseTableMax`）配合双指针，判断每个窗口的 max-min 是否 ≤ limit，练的是把两类幂等稀疏表同时用在一个判定条件上。
