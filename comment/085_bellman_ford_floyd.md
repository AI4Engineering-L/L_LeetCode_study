# N085 · Bellman-Ford、受限路径与Floyd —— 说人话详解

> 对应 notebook：`notebooks/11_graphs/085_bellman_ford_floyd.ipynb`

## 一、这章要解决什么问题？（问题描述）

这一章研究的都是"最短路"问题，但比普通 BFS 最短路多了三种新情况：

1. **边权可能是负数**。比如从 A 到 B 的花费是 -3（走这条边反而赚钱），这时 Dijkstra 就不适用了，我们需要 Bellman-Ford。
2. **路径的边数被限制**。LeetCode 787 那种"最多中转 k 站"的机票题：你从城市 0 飞到城市 2，但规定最多只能坐 k+1 段航班，问最低票价。这时不能无限制地用最便宜的走法，因为最便宜的走法可能绕太远、边数超了。
3. **想知道"所有点对"之间的最短路**。也就是任选两个城市 i 和 j，都要知道 i 到 j 的最短距离，这就是 Floyd 算法干的事。

给一个具体到数字的例子（这就是 notebook 里反复用的机票例子）：有 3 个城市，航班表是 `flights=[(0,1,100),(1,2,100),(0,2,500)]`，意思是 0→1 票价 100，1→2 票价 100，0→2 直飞票价 500。

- 如果**不允许中转**（k=0，只能坐 1 段航班）：你只能直飞，答案是 **500**。
- 如果**允许中转 1 站**（k=1，最多坐 2 段航班）：你可以先飞 0→1 再飞 1→2，总花费 100+100=**200**。

同样是"从 0 到 2 最便宜"，约束一变答案就从 500 变成 200，这就是"限制边数"的含义，也是这一章要讲清楚的核心区别。

## 二、关键概念（定义）

- **松弛（relaxation）**：对一条边 u→v（权重 w），如果你发现"先到 u 的代价 + 这条边的代价"比"目前记录的到 v 的代价"更小，就把 v 的距离更新成更小的那个值。比如目前 `distance[1]=200`，边 1→2 权重 100，那么 200+100=300 比当前 `distance[2]=500` 小，就把 `distance[2]` 改成 300。每一次这样的"尝试更新"就叫一次松弛。
- **分轮松弛**：Bellman-Ford 把所有边扫一遍叫"一轮"。做完一轮，至少能保证"用 1 条边能到达的最短路"都算对了；做完两轮，"用 2 条边的"也对了……依此类推。
- **上一轮副本（快照）**：在限制边数的问题里，第 t 轮的更新只能基于第 t-1 轮结束时的距离表，所以每轮开始要先复制一份旧表（`new=distance[:]`），所有读取都读旧表，写都写新表。否则一轮之内就会"边用边更新"，等于偷偷在一轮里连用了好几条边，违反 K 站限制。
- **负边**：权重为负的边。它本身不可怕，Bellman-Ford 照样能处理。
- **负环（负环回路）**：一圈走下来总权重为负的环。比如 1→2 权重 -3、2→1 权重 1，绕一圈净赚 2。如果源点能到达负环，"最短路"就不存在了——你可以绕无限多圈让距离趋向负无穷。Bellman-Ford 的额外本事就是能检测出这种情况。
- **全源 DP（Floyd）**：DP 是动态规划。Floyd 用一张 n×n 的距离表，`distance[i][j]` 表示"目前所知的 i 到 j 最短距离"，通过逐个引入"允许经过的中间点"来填表，最后一张表就是所有点对的最短路。
- **中间点顺序**：Floyd 的三层循环里，最外层必须是"中间点 k"。也就是说我们是按"允许经过点 0 → 允许经过点 0,1 → 允许经过点 0,1,2 …"这样的顺序逐步放开中间点的，这个顺序不能和内层的 i、j 随便调换，调换了结果就是错的。
- **距离阈值（threshold）**：LeetCode 1334 里的概念——只有距离不超过 threshold 的城市才算"邻居"。我们要找的是"邻居数量最少的城市"，邻居数相同时选编号最大的。

## 三、解决思路（一步步推导）

### Bellman-Ford（普通最短路 + 负环检测）

- **Step 1**：把到每个点的距离初始化为无穷大 `inf`，只有源点自己是 0。无穷大的意思是"目前认为根本到不了"。
- **Step 2**：把所有边完整地扫一遍，能松弛就松弛，这叫一轮。一共做 n-1 轮（n 是点数）。
- **Step 3**：如果某一轮做完一次松弛都没发生（`changed` 还是 False），说明距离表已经稳定，提前跳出，省时间。
- **Step 4**：n-1 轮之后再额外检查一遍所有边：如果还有边能松弛，说明存在从源点可达的负环，返回标记 `negative_cycle=True`，此时距离表里的数字不能当作真实最短路用。

**手算演示**（对应测试里的图）：点数 n=3，边 `(0,1,1),(1,2,-3),(2,1,1)`，源点 0。

- 初始：`distance=[0, inf, inf]`。
- 第 1 轮扫边：0→1 权 1，0+1=1 < inf，更新，`distance[1]=1`；1→2 权 -3，1+(-3)=-2 < inf，更新，`distance[2]=-2`；2→1 权 1，-2+1=-1 < 1，更新，`distance[1]=-1`。此时表为 `[0, -1, -2]`。
- 第 2 轮再来一遍：0→1 还是得 1，不比 -1 小；1→2 得 -1+(-3)=-4 < -2，更新，`distance[2]=-4`；2→1 得 -4+1=-3 < -1，更新，`distance[1]=-3`。
- 你看出来了吧：1→2→1 这个环每绕一圈总距离就减 2，永远可以继续改进。这就是负环，做了 n-1=2 轮之后再来检查，1→2 这条边仍然能松弛（-3+(-3)=-6 < -4），所以 `negative_cycle=True`。这正是测试 `assert bellman_ford(3,[(0,1,1),(1,2,-3),(2,1,1)],0)[1]` 通过的原因（`[1]` 取的是返回元组第二项）。

### 受限边数的最短路（cheapest_flights）

- **Step 1**：和 Bellman-Ford 一样初始化距离表。
- **Step 2**：每轮开始先复制旧表 `new=distance[:]`，这一步是整个函数的灵魂——保证本轮所有松弛读的都是"上一轮结束时"的距离。
- **Step 3**：对每条边 (u,v,w) 用旧表算 `new[v]=min(new[v], distance[u]+w)`。注意右边读的是 `distance`（旧表），左边写的是 `new`（新表）。
- **Step 4**：做 k+1 轮（最多中转 k 站 = 最多 k+1 条边）。最后看 `distance[dst]`，还是无穷大就说明根本到不了，返回 -1。

**手算演示**（notebook cell6 的表格数据就是它）：`flights=[(0,1,100),(1,2,100),(0,2,500)]`，从 0 到 2。

- k=0（1 轮）：第 1 轮里扫到 0→2，`new[2]=min(inf, 0+500)=500`。扫到 1→2 时读旧表 `distance[1]=inf`，没用。答案 **500**。
- k=1（2 轮）：第 1 轮结束后 `distance=[0,100,500]`；第 2 轮扫 1→2，读旧表 `distance[1]=100`，得 `new[2]=min(500,100+100)=200`。答案 **200**。
- k=2（3 轮）：不会再有改进，答案还是 **200**。

cell6 的 show_table 表格正是把 (k=0,1,2) 三种情况列成了表：最多边数 1→500、最多边数 2→200、最多边数 3→200。

**反过来想一个坑**：如果不用快照、直接在原表上松弛，第 1 轮扫完 0→1 马上更新 `distance[1]=100`，接着扫到 1→2 时立刻用上这个 100，一轮之内就连坐了两段航班，k=0 也会错误地算出 200。这就是练习 1 要你亲手构造的反例。

### Floyd（全源最短路）

- **Step 1**：建一张 n×n 表，全部填 `inf`，对角线（自己到自己）填 0；再把每条边填进去（重复边取小的）。
- **Step 2**：最外层循环 k 从 0 到 n-1，含义是"现在开始允许把点 k 当作中转站"。
- **Step 3**：对每一对 (i,j)，比较"直接走"和"先从 i 到 k、再从 k 到 j"，取较小者：`distance[i][j]=min(distance[i][j], distance[i][k]+distance[k][j])`。
- **Step 4**：k 循环全部跑完，表里就是任意两点的最短路。

**手算演示**：n=2，边 `(0,1,5),(0,1,2)`（两点间两条平行边）。初始化时用 `min` 处理重复边，`distance[0][1]` 先填 5、再被 2 覆盖。k 循环里没有任何中转能更短，最终 `distance[0][1]=2`。这对应测试 `assert floyd_warshall(2,[(0,1,5),(0,1,2)])[0][1]==2`。

### find_the_city（Floyd 的应用）

- **Step 1**：先跑一遍无向版的 Floyd（`directed=False`，反向边也填表）。
- **Step 2**：对每个城市 i，数一数有多少个 j（j≠i 且 `distance[i][j]<=threshold`），这就是"阈值内的邻居数"。
- **Step 3**：用 `min(..., key=...)` 挑邻居数最小的城市；邻居数打平时，用 `-i` 当第二关键字让编号大的胜出（`-i` 越小意味着 i 越大）。

## 四、代码逐段讲解

### 函数 1：`bellman_ford(n, edges, source)`

```python
def bellman_ford(n,edges,source):
    distance=[float('inf')]*n; distance[source]=0
    for _ in range(n-1):
        changed=False
        for u,v,w in edges:
            if distance[u]+w<distance[v]: distance[v]=distance[u]+w; changed=True
        if not changed: break
    negative_cycle=any(distance[u]+w<distance[v] for u,v,w in edges)
    return distance,negative_cycle
```

- 第 1 行定义函数签名：n 个点、边列表 edges（每条边是 `(u,v,w)` 三元组）、源点 source。
- 第 2 行先造长度 n 的距离表全填无穷大，再把源点设成 0。用分号把两句写在同一行，是紧凑写法，语义完全等价于两行。
- 第 3 行 `for _ in range(n-1)`：主循环最多 n-1 轮。变量名用 `_` 表示"我们根本不关心这是第几轮"。
- 第 4 行 `changed=False`：本轮是否发生过松弛的标记，用来提前退出。
- 第 5 行遍历每条边做松弛：如果"到 u 的距离 + 边权"比"当前到 v 的距离"更小，就更新 v，并记 `changed=True`。
- 第 6 行 `if not changed: break`：一整轮没发生任何松弛，说明表已经收敛，剩下的轮次不用跑了。这是纯优化，不影响正确性。
- 第 7 行在 n-1 轮之后再检查一遍所有边：`any(...)` 只要有一条边还能松弛就返回 True，这就是负环检测——正常情况下 n-1 轮后不可能再松弛了，还能松弛只能是负环在捣鬼。
- 第 8 行返回一个元组 `(距离表, 是否有可达负环)`。

### 函数 2：`cheapest_flights(n, flights, src, dst, k)`

```python
def cheapest_flights(n,flights,src,dst,k):
    distance=[float('inf')]*n; distance[src]=0
    for _ in range(k+1):
        new=distance[:]
        for u,v,w in flights: new[v]=min(new[v],distance[u]+w)
        distance=new
    return -1 if distance[dst]==float('inf') else distance[dst]
```

- 第 2 行初始化和 Bellman-Ford 一模一样。
- 第 3 行 `range(k+1)`：最多中转 k 站等价于最多坐 k+1 条边，所以跑 k+1 轮，每一轮"最多再多用一条边"。
- 第 4 行 `new=distance[:]`：切片复制，造一份旧表快照。注意是浅拷贝列表本身，够用了。
- 第 5 行是核心一行：对每条边，读**旧表** `distance[u]`，写**新表** `new[v]`，用 `min` 保证只减不增。正因为读旧写新，一轮之内不可能连用两条新边。
- 第 6 行 `distance=new`：本轮结束，新表变成下一轮的旧表。
- 第 7 行是 Python 的条件表达式（三元写法）：终点距离还是无穷大说明到不了，按题意返回 -1；否则返回最便宜票价。

### 函数 3：`floyd_warshall(n, edges, directed=True)`

```python
def floyd_warshall(n,edges,directed=True):
    distance=[[float('inf')]*n for _ in range(n)]
    for i in range(n): distance[i][i]=0
    for u,v,w in edges:
        distance[u][v]=min(distance[u][v],w)
        if not directed: distance[v][u]=min(distance[v][u],w)
    for k in range(n):
        for i in range(n):
            if distance[i][k]==float('inf'): continue
            for j in range(n): distance[i][j]=min(distance[i][j],distance[i][k]+distance[k][j])
    return distance
```

- 第 2 行用列表推导造 n×n 的表，全部填无穷大。注意必须用推导式一行行造，不能 `[[inf]*n]*n`（那样所有行共享同一个列表，改一处会处处变）。
- 第 3 行对角线填 0：自己到自己距离为 0。
- 第 4–6 行把每条边填进表：`min` 是为了处理两点间有多条平行边时保留最短的；参数 `directed` 默认为 True 表示有向图，传 False 时把反向 `distance[v][u]` 也填上，用于无向图。
- 第 7–11 行是三重循环：外层 k 是"新放开的中间点"，内层 i、j 是起点终点。核心更新就是第 11 行的 `min`。
- 第 10 行 `if distance[i][k]==float('inf'): continue` 是个剪枝：如果 i 根本到不了 k，那"经 k 中转"这条路根本不存在，内层 j 的循环全白跑，直接跳过这一行 i，能省不少时间。

### 函数 4：`find_the_city(n, edges, threshold)`

```python
def find_the_city(n,edges,threshold):
    distance=floyd_warshall(n,edges,False)
    return min(range(n),key=lambda i:(sum(i!=j and distance[i][j]<=threshold for j in range(n)),-i))
```

- 第 2 行直接复用 Floyd，注意第三个参数传 `False`，因为这道题的城市道路是双向的。
- 第 3 行一句完成选城市：`min` 配 `key` 函数。对每个候选城市 i，key 是一个二元组 `(邻居数量, -i)`。二元组比较是先比第一项、相同再比第二项，所以"邻居最少者优先；打平的时候 `-i` 更小（也就是 i 编号更大）者胜"。这正好对应 LeetCode 1334 的规则。
- `sum(... for j ...)` 里那个生成式逐个判断 j：j 不是 i 自己、且 `distance[i][j]` 不超过阈值就计 1，加起来就是邻居数。

## 五、为什么是对的？复杂度是多少？（说人话）

**Bellman-Ford 为什么做 n-1 轮就够？** 我们这么想：一张没有负环的图里，最短路不会绕回头路，所以任何一条最短路最多经过 n-1 条边（n 个点的路径最多串起 n 个点、用 n-1 条边）。而每完整做一轮松弛，"最多用 t 条边能到的最优答案"就一定算准了，接着下一轮又把 t+1 条边的算准。所以 n-1 轮之后，所有可能的边数都覆盖到了，答案不会再变。如果 n-1 轮之后还能改进，那只能是某条路超过了 n-1 条边还在变短——这只有在环上打转且每圈变短（负环）时才会发生，所以这个检测是可靠的。反过来看测试里那个 `[(1,2,-3),(2,1,1)]` 的例子：源点 0 根本没有出边，到不了那个负环，所以检测结果是 False——负环只有"从源点可达"时才影响答案，这条测试就是在验证这一点。

**Floyd 为什么对？** 我们按"允许经过的中间点编号"一层层放开。当处理到某个 k 时，表里存的是"只允许在编号小于 k 的点中转时的所有点对最短路"。此时 i 到 j 的最优走法只有两种可能：要么不经过 k（表里现在的值就够好），要么经过 k——那这段路必然拆成"i 到 k"和"k 到 j"两半，而这两半都不需要经过 k（最短路不会经过同一个点两次），所以它们已经是前几步算准的值了。两种取较小，就得到了"允许中转点 0..k"的正确答案。这也是为什么最外层必须是 k：如果 k 放到内层，你在算"经 k 中转"时用的可能还是没算准的值，结果就错了。

**复杂度，用具体数字说：**

- Bellman-Ford 是 O(V×E)：每一轮把 E 条边全扫一遍，最多 V-1 轮。比如 100 个点、1000 条边的小图，最多约 10 万次比较，一瞬间就算完；但如果是 10⁴ 个点、10⁴ 条边，就是约 10⁸ 次操作，会明显变慢。空间只需要一张距离表，O(V)。
- 受限路径版是 O((k+1)×E)：只跑 k+1 轮而不是 V-1 轮。k 通常很小（机票题里 k ≤ 100 左右），所以非常快。空间同样是 O(V)。
- Floyd 是 O(V³) 时间、O(V²) 空间：三重循环每层都是 n。n=100 时约 10⁶ 次操作，很快；n=500 时约 1.25×10⁸ 次，还行；n=2000 时约 8×10⁹ 次，就撑不住了。所以 Floyd 适合"点少边多、又要所有点对答案"的场景。
- cell4 还提到一个细节：如果图里有负环，Floyd 跑完对角线 `distance[i][i]` 会变成负数，可以借此检测负环；但本 notebook 的 floyd_warshall 函数并没有把所有"被负环污染成负无穷"的点对标记出来，这个能力它不承诺。

## 六、测试用例在测什么

```python
f=[(0,1,100),(1,2,100),(0,2,500)]
assert cheapest_flights(3,f,0,2,0)==500 and cheapest_flights(3,f,0,2,1)==200
```
这条测的是受限路径的正常值：k=0 时只能直飞所以是 500，k=1 时能中转所以是 200。两个值一起验证"边数限制确实生效"，如果实现忘了用快照，k=0 会错误地算出 200，这条就挂了。

```python
assert cheapest_flights(3,f,2,0,2)==-1
```
这条测的是"到不了"的特殊情况：所有航班都是单向的 0→1→2 方向，从 2 出发根本回不到 0，距离保持无穷大，按契约应返回 -1。

```python
assert floyd_warshall(2,[(0,1,5),(0,1,2)])[0][1]==2
```
这条测的是 Floyd 对平行边的处理：0 到 1 有两条边（5 和 2），正确实现应保留较短的 2。它顺便验证了初始化时用 `min` 填边的必要性。

```python
assert bellman_ford(3,[(0,1,1),(1,2,-3),(2,1,1)],0)[1]
```
这条测的是负环检测的正例：源点 0 能到达 1→2→1 这个负环，返回元组的第二项（用 `[1]` 取）应为 True。我们在第三节已经手算过这个过程。

```python
assert not bellman_ford(3,[(1,2,-3),(2,1,1)],0)[1]
```
这条测的是负环检测的反例：负环还在（1 和 2 之间），但源点 0 没有任何出边、根本走不到那里，所以"从源点可达的负环"不存在，应返回 False。这条防止实现犯"见到负环就报警"的过度检测错误。

```python
assert find_the_city(4,[(0,1,3),(1,2,1),(1,3,4),(2,3,1)],4)==3
```
这条测的是找城市的完整逻辑。4 个城市、无向边。算出全源距离后：城市 0 在阈值 4 内能到 1（距离 3），到 2 要 3+1=4 也算、到 3 是 min(3+4, 3+1+1)=4 也算，共 3 个邻居；城市 3 能到 2（1）、到 1（2）、到 0（4 是通过 1 的 3+4 还是 2+1+1=... 直接连边是 4，满足 ≤4），也是 3 个邻居。0 和 3 打平，按规则选编号大的 3。

```python
from random import Random
rng=Random(85)
for _ in range(80):
    n=5; edges=[(u,v,rng.randrange(6)) for u in range(n) for v in range(n) if rng.randrange(4)==0]
    allpairs=floyd_warshall(n,edges)
    for source in range(n):
        dist,negative=bellman_ford(n,edges,source)
        assert not negative and dist==allpairs[source]
```
这段是随机对拍：固定随机种子 85（保证每次运行生成同一批图，可复现），生成 80 张 5 点随机图，边权取 0 到 5（非负，所以不可能有负环）。对每张图，把每个点当源点跑 Bellman-Ford，结果必须和 Floyd 整表的对应行完全一致。两个独立算法在几十张随机图上答案全部吻合，这是很强的正确性证据——虽然它仍是测试而非证明。

## 七、练习思路提示

**练习 1：构造"原地松弛违反 K 站限制"的例子。**
思路方向：找一张图，其中"必须多用一条边才能拿到更低价"的路径存在。提示：我们正文用的机票图就是现成素材——在正确实现里 k=0 的答案是 500；你只要写一个"把 `new=distance[:]` 快照删掉、直接在 distance 上更新"的错误版本，对同一输入跑一遍，观察它 k=0 时也会给出 200。验收时要写清楚输入、期望输出（正确版）、错误版的输出，并解释错误版为什么在一轮里连用了 0→1 和 1→2 两条边。

**练习 2：对自编图加入可达负环检测。**
思路方向：先自己画一张含负环的图，并保证源点能走到环上。提示：可以直接扩展正文的手算例子——在 `(0,1,1),(1,2,-3),(2,1,1)` 基础上再加一两个点和边，比如让负环藏在"源点走两步才能到"的位置；然后调用 `bellman_ford`，检查返回的第二项是不是 True。再做一个对照：删掉源点到环的通路，确认第二项变 False。手算演示可以抄我们第三节的轮次表格式，一轮一轮列出 distance 的变化，展示"每轮都在变好、永不收敛"的现象。
