# N035 · 区间合并、插入与交集 —— 说人话详解

> 对应 notebook：`notebooks/04_prefix_intervals/035_interval_union_intersection.ipynb`

## 一、这章要解决什么问题？（问题描述）

这一章处理三件和区间有关的基础事务，全部采用**闭区间**约定（[left,right] 两端都算在内的整数区间）。

**问题 A（合并重叠区间）**：给一堆区间，把互相重叠或相接的合并成一块，输出合并后的不相交区间列表。具体例子：输入 `[[1,3],[2,6],[8,10]]`，输出 `[[1,6],[8,10]]`。为什么？[1,3] 和 [2,6] 有公共部分 [2,3]，合成 [1,6]；[8,10] 和 [1,6] 不挨着（6 < 8），自己一段。

**问题 B（插入新区间）**：给定一个**已经互不重叠**的区间列表和一个新区间，插入后返回合并好的列表。具体例子：输入 `[[1,2],[5,7]]`、新区间 `[2,6]`，输出 `[[1,7]]`。因为 [2,6] 把 [1,2] 和 [5,7] 连了起来：[1,2] 与 [2,6] 在端点 2 相接，[2,6] 与 [5,7] 在 [5,6] 重叠，三者连成 [1,7]。

**问题 C（两列区间求交集）**：给两列各自有序且互不重叠的区间，求它们的公共部分。具体例子：输入 `[[1,2]]` 和 `[[2,3]]`，输出 `[[2,2]]`——两条闭区间只共享整数点 2，按闭区间约定这算一个（退化的）交集区间。

贯穿三件事的同一个主题是：**先按端点排序，再从左到右扫描，用"当前已合并区间的最远右端"做决策**。这三个函数也是日程系统、时间线合并、会议安排类实际场景的底层零件。

## 二、关键概念（定义）

- **闭区间 [l,r]**：l 和 r 之间的所有整数（含两端）。两条闭区间"相接"（比如 [1,2] 和 [2,3] 共享点 2）也算相交，可以合并——这是本章的明确约定，练习 1 会让你对比半开约定下的差别。
  - 为什么约定这么重要？因为"相邻端点算不算重叠"直接决定合并条件的等号写在哪一侧，也决定求交时单点交集（如 [2,2]）是否合法输出。开闭约定含糊，代码就处处是坑。
- **重叠判定**：两条闭区间 [a1,b1]、[a2,b2] 相交当且仅当 `max(a1,a2) <= min(b1,b2)`。本章代码里更轻量：因为处理前已按左端排序（当前区间的左端不小于已合并段），只需检查"当前左端是否超过已合并段的右端"，超过才另开新段。求交函数用的正是完整版判定 `left<=right`——因为两列区间互不保证谁在谁左边，不能用简化版。
- **排序扫描**：先把区间按左端点从小到大排序，再从左到右处理。排序保证"后面来的区间左端不会比前面更靠左"，所以已合并段的左端一旦确定就不必再改，只有右端可能被不断推远。
- **已合并段的最远右端**：`merged[-1][1]`，即当前这一大块覆盖到的最右位置。来新区间 [l,r] 时只问一句话：l 是否比这个右端还大？是，说明中间断了，另开一段；否，说明连得上，把右端更新为 `max(旧右端, r)`（r 可能反而更小，比如 [1,4] 吞掉 [2,3]，右端保持 4）。
- **双指针求交**：两列各自有序的区间求交集时用 i、j 两个下标各管一列。每步用 `max(左端)` 和 `min(右端)` 算出候选交集，谁先结束谁前进——因为**先结束的那条**不可能再和对方后面的任何区间相交（对方后面的区间更靠右），移动它是安全的。
- **规范化输出**：合并结果保持按左端升序、互不相交、每段左右端合法（不出现左>右）。输入里的"倒挂区间"（如 [5,3]）在合并函数里直接抛 ValueError 拒收，这是防御式处理。

## 三、解决思路（一步步推导）

问题 A（合并）的推导：

- **Step 1**：把所有区间按左端排序（Python `sorted(intervals)` 对 [l,r] 列表默认先比 l 再比 r，正好）。
- **Step 2**：逐个取出区间 [l,r]。若结果列表为空、或 l 大于已合并段的右端，说明不相连，另起新段 [l,r]。
- **Step 3**：否则相连，把已合并段的右端推到 `max(原右端, r)`。
- **Step 4**：处理完所有区间即是答案。因为输入有序，已合并段的左端只会来自更早的区间，永不需要回改。

手算演示（`a=[[1,3],[2,6],[8,10],[10,12]]`，cell6 的数据），逐前缀看合并结果：

| 处理到 | 新区间 | 判断 | 合并后 |
|---|---|---|---|
| 第 1 个 | [1,3] | 列表空，直接放入 | [[1,3]] |
| 第 2 个 | [2,6] | 2 ≤ 3，相连；右端 max(3,6)=6 | [[1,6]] |
| 第 3 个 | [8,10] | 8 > 6，断开，另起 | [[1,6],[8,10]] |
| 第 4 个 | [10,12] | 10 ≤ 10，相接也算相连；右端 max(10,12)=12 | [[1,6],[8,12]] |

这四行正是 notebook cell6 用 `show_table` 打印的表（列：处理前缀、合并后）。注意最后一行：[8,10] 和 [10,12] 只共享端点 10，按闭区间约定仍合并——这是最容易被忽略的细节。

问题 B（插入）：把新区间追加进旧列表后直接调用合并函数。旧列表本来就有序不重叠，追加一个元素再排序代价可忽略（cell4 也提到：若输入已排序可进一步做成线性插入，本章取简洁写法）。

手算演示（`intervals=[[1,2],[5,7]]`、`new=[2,6]`，cell8 的数据）：追加并排序后得 [[1,2],[2,6],[5,7]]，走一遍合并：

| 处理到 | 区间 | 判断 | merged |
|---|---|---|---|
| 1 | [1,2] | 列表空，放入 | [[1,2]] |
| 2 | [2,6] | 2 ≤ 2，相接合并；右端 max(2,6)=6 | [[1,6]] |
| 3 | [5,7] | 5 ≤ 6，重叠合并；右端 max(6,7)=7 | [[1,7]] |

结果 [[1,7]]：新区间像一座桥，把原本分开的两段焊在了一起。

问题 C（求交）的推导：

- **Step 1**：双指针 i、j 分别指向两列区间。
- **Step 2**：取 `left=max(a[i].l, b[j].l)`、`right=min(a[i].r, b[j].r)`。若 left ≤ right，这一段就是一组真实交集，收进答案。
- **Step 3**：比较两当前区间的右端，**右端小的那条**指针前进一步。它都结束了，对方后面再长的区间也与它无缘。
  - 为什么不能走右端大的那条？因为它还活着，对方后面的区间（更靠右但左端仍可能小于它的右端）还有机会和它相交，走了就丢答案。
- **Step 4**：任一指针走到头就结束。

手算演示（`a=[[1,2]]`、`b=[[2,3]]`）：left=max(1,2)=2，right=min(2,3)=2，left ≤ right，收 [2,2]；a[0] 右端 2 < 3，i 前进越界，结束，答案 [[2,2]]。

## 四、代码逐段讲解

先看 `merge_intervals`，逐字照抄如下：

```python
def merge_intervals(intervals):
    merged=[]
    for left,right in sorted(intervals):
        if left>right: raise ValueError('reversed interval')
        if not merged or left>merged[-1][1]: merged.append([left,right])
        else: merged[-1][1]=max(merged[-1][1],right)
    return merged
```

- `merged=[]`：结果列表，维持"从左到右、互不相交"的性质。
- `for left,right in sorted(intervals):`：排序后逐个解包。`sorted(intervals)` 返回按左端（左端相同再按右端）升序的新列表，不动原输入。
- `if left>right: raise ValueError('reversed interval')`：挡住倒挂区间（如 [5,3]）。这种输入语义不明，与其给一个错误结果不如立刻报错。
- `if not merged or left>merged[-1][1]: merged.append([left,right])`：两个另起新段的条件——结果列表还是空的，或当前左端严格大于已合并段右端（中间有空隙）。注意用的是严格大于：等于（端点相接）落入 else 分支参与合并，这正是闭区间约定的体现。
- `else: merged[-1][1]=max(merged[-1][1],right)`：相连时只改右端。取 max 是因为新区间可能被已合并段完全包含（[1,4] 之后的 [2,3]），此时右端不该被拉小。
- `return merged`：列表本身已按左端有序，直接返回。

再看 `insert_interval`，逐字照抄如下：

```python
def insert_interval(intervals,new):
    return merge_intervals([*intervals,list(new)])
```

- `[*intervals,list(new)]`：解包旧列表再拼上新区间。`list(new)` 把传入的区间复制成新列表，避免和调用方共享可变对象。整体等价于 `intervals + [list(new)]`，作者用星号解包是等价写法。
- 一行完成"插入 = 追加 + 重合并"。正确性依赖一个事实：对互不重叠且有序的输入，追加一个元素后重新合并，结果和手工线性插入完全一致。

最后看 `interval_intersection`，逐字照抄如下：

```python
def interval_intersection(a,b):
    i=j=0; answer=[]
    while i<len(a) and j<len(b):
        left=max(a[i][0],b[j][0]); right=min(a[i][1],b[j][1])
        if left<=right: answer.append([left,right])
        if a[i][1]<b[j][1]: i+=1
        else: j+=1
    return answer
```

- `i=j=0; answer=[]`：两个指针管两列，answer 收交集。
- `while i<len(a) and j<len(b):`：任何一列走完就停——剩下的那列再长也配不到对。
- `left=max(a[i][0],b[j][0]); right=min(a[i][1],b[j][1])`：候选交集的左右端，分别是两个左端的较大者和两个右端的较小者。
- `if left<=right: answer.append([left,right])`：左端不超过右端说明真有公共部分，收下（相等时是单点交集，如 [[2,2]]）。否则这对区间不相交，什么都不收。
- `if a[i][1]<b[j][1]: i+=1` else `j+=1`：右端较小的那条先走。理由：对方后面的区间左端只会更大，先结束的这条不可能再和它们相交；两右端相等时走哪个都行（else 分支走 j），走的那条与对方当前区间的交集已经在上面收过了。
  - 拿 [[1,5]] 与 [[2,3],[4,6]] 走一遍：先配 [1,5]×[2,3] 得 [2,3]，b[0] 右端 3 < 5，j 前进；再配 [1,5]×[4,6] 得 [4,5]，a[0] 右端 5 < 6，i 前进越界结束，答案 [[2,3],[4,5]]。可见 a 的同一条区间可以连续配 b 的多条，这正是"谁结束谁走"的威力。
- `return answer`：交集天然按左端有序（因为两指针都只前进）。

## 五、为什么是对的？复杂度是多少？（说人话）

**为什么对（合并）**：排序之后，后面区间的左端不会比前面更靠左。所以当某个新区间的左端大于已合并段的右端时，它们之间真正断开了，而且**之后的所有区间**左端只会更大，更接不上这一段——这段就此封口，永不被后续桥接，另起一段是安全且必要的。相连时右端取 max，保证已合并段始终覆盖住"到目前为止见过的所有区间"，一个不漏。

**为什么对（求交）**：任意时刻，a[i] 和 b[j] 是双方尚未配完的第一对候选。若它们相交，公共部分就是 [max 左端, min 右端]，没有别的可能。然后右端小的那条前进：它和对方**当前**这条的交集已收，和对方**后面**的区间（左端更大）更不可能有交集，所以丢掉它不损失任何答案；右端相等时两边都已互相配完，走哪边都行。两指针都单调前进，穷尽了所有可能的配对。

**复杂度**：合并的瓶颈是排序，O(n log n)；排序后的单趟扫描每步 O(1)，共 O(n)。插入走合并，同样 O(n log n)（若输入已排序，可以写线性扫描的特化版做到 O(n)，本章为简洁不做）。求交两个指针各走自己一列，O(n+m)，答案空间与交集个数一致。具体数字：十万条区间排序约 10^5×17≈170 万次比较，毫秒级完成；若不排序直接两两比较判重叠，是百亿次的量级，根本不可行。

## 六、测试用例在测什么

cell8 的断言逐条解释：

- `assert merge_intervals([[1,3],[2,6],[8,10]])==[[1,6],[8,10]]`：正常值测试。部分重叠要合并、不相连要分开，验证主判断分支。
- `assert merge_intervals([[1,4],[2,3],[4,5]])==[[1,5]]`：特殊值测试，两个考点。其一，[2,3] 被 [1,4] 完全包含，验证右端取 max（而不是盲目覆盖成 3）；其二，[1,4] 与 [4,5] 端点相接（共享 4）也要合并成 [1,5]，验证闭区间"相接即相交"的约定。
- `assert insert_interval([[1,2],[5,7]],[2,6])==[[1,7]]`：正常值测试。新区间恰好横跨两段并各自相接/重叠，把两段连成一整段，验证"插入=追加+重合并"的等价性。
- `assert interval_intersection([[1,2]],[[2,3]])==[[2,2]]`：边界值测试。两条区间只共享单个端点 2，闭区间约定下应产出退化交集 [2,2] 而不是空——这条卡"用左端<右端判断"导致丢掉单点交集的写法。
- 随机段：`rng=Random(35)` 固定种子。100 轮，每轮生成 5 条随机区间（端点取 0~5，先排序保证左≤右）。检查两件事：一是合并结果内部**严格分离** `m[i][1]<m[i+1][0]`——用严格小于，因为闭区间相接本就该被合并，留下的段之间必须真正有空隙；二是对 0~5 的全部半格点 x（0, 0.5, 1, …, 5）验证"点被原区间覆盖"与"点被合并结果覆盖"完全一致，等价于并集没变。半格点是巧妙的一手：相邻整数端点产生的空隙最小宽度是 1，半格采样足以区分"断开"与"相接"。两条检查合起来的含义是：合并**只做了规范化，没有改变覆盖范围**——既没多合并（性质一保证分离）也没漏合并（性质二保证并集不变）。

## 七、练习思路提示

- **练习 1（比较闭区间与半开区间的相邻合并条件）**：提示：两种约定下"另起新段"的分界差一个等号。闭区间下 `left > merged[-1][1]` 才断开（端点相等算相连）；半开 [l,r) 下 `left >= merged[-1][1]` 就断开（[1,2) 与 [2,3) 不共享任何点）。用同一组输入 `[[1,2],[2,3]]` 分别手算两种约定的结果：闭区间得 [[1,3]]，半开得 [[1,2),[2,3)] 两段。练习要求你写明输入输出与边界再验证，这个例子就是最小的边界反例。
- **练习 2（输出覆盖总长度）**：提示：合并之后，总覆盖长度就是各段 `right−left` 之和（闭整区间 [l,r] 覆盖 r−l+1 个整数点，若题目问"点数"要加一；若按数轴长度算是 r−l，先想清楚题目口径）。既然合并结果互不相交，直接求和就不会重复计算重叠部分——这正是"先规范化再统计"的好处。验证可用 `[[1,3],[2,6],[8,10],[10,12]]`：合并成 [[1,6],[8,12]]，长度 = 5+4 = 9（数轴口径），与逐段暴力去重数格子的结果对拍。

## 八、对应 LeetCode 题目

- **56. Merge Intervals**：这题就是 `merge_intervals` 的原题（合并所有重叠区间），练的是"按左端排序 + 最远右端决策"的主套路。这题输入不保证有序，所以代码里 `sorted(intervals)` 那步不能省；判重、日程合并、时间线压缩类题目大都是它的变体。
- **57. Insert Interval**：这题就是 `insert_interval` 的原题（往有序不重叠列表里插入并合并），本章"追加后重合并"是正确性等价的简洁解法，题解区常见的线性三段式扫描是它的优化版。面试里若被追问"能否不排序"，就轮到三段式出场：新区间左侧直接抄、重叠段融合、右侧直接抄。
- **986. Interval List Intersections**：这题就是 `interval_intersection` 的原题（两列有序区间求交集），练的是"max 左端/min 右端取交集 + 先结束者前进"的双指针配对。这题输入保证两列各自有序不重叠，正是双指针正确性的前提；若输入无序，得先排序再套本章代码。
