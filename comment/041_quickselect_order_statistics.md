# N041 · 快速选择与第K大 —— 说人话详解

> 对应 notebook：`notebooks/05_sort_binary_search/041_quickselect_order_statistics.ipynb`

## 一、这章要解决什么问题？（问题描述）

这一章解决的问题是：**只要数组里第 k 小（或第 k 大）的那一个元素，不想为它把整个数组排完**。排全序是 O(n log n)，但"选一个秩"可以更快：快速选择期望 O(n)——快排的划分动作做完之后，看目标落在哪一侧，**只追一侧、丢另一侧**。

先看具体到数字的例子（cell8 的真实数据）：

- 输入：`nums = [3,2,1,5,6,4]`，求第 2 大
- 输出：`5`
- 为什么是 5？把数组排成 [1,2,3,4,5,6]，从大到小数：第 1 大是 6、第 2 大是 5。注意我们**只关心 5 这一个值**，1、2、3、4 的相对顺序根本不需要知道——这就是快速选择能省事的根源。

本章接口的秩约定要分清：`quickselect(a, k)` 里的 k 是**零基第 k 小**（k=0 是最小值、k=n-1 是最大值）；对外常用的"第 k 大"是 1 基的，换算方法是：第 k 大 = 零基第 (n−k) 小。上例 n=6、k=2，所以求的是零基第 4 小，sorted(a)[4] = 5，对上了。

## 二、关键概念（定义）

- **秩（rank / 顺序统计量）**：元素在有序版本中的位置。零基第 k 小 = 排完序后下标 k 上的那个值。第 k 大（1 基）与零基第 k 小的换算是 n−k。
- **三路划分（three-way partition）**：沿用 N039 的动作——选枢轴，把当前窗口分成"严格小于 | 等于 | 严格大于"三段。本章在 quickselect 里内联了同一段三指针循环。
- **等值块（equal block）**：划分后所有等于枢轴的元素连成的一段 [lt, gt)。它们的最终位置已经确定：把窗口从小到大排好后，这一段恰好落在秩 lt..gt-1 上。
- **只递归一侧（单侧递归）**：划分完看目标秩 k 落在哪段：落在小于段就把窗口缩到小于段，落在大于段就缩到大于段，落在等值块里答案直接就是枢轴值——每轮丢掉一整侧，这是快速选择比快排快的全部原因。
- **随机化（randomization）**：枢轴从当前窗口随机抽取。它不改变答案对不对，只把"每次都挑到坏枢轴"变成小概率事件，从而把**期望**代价压到 O(n)。
- **期望 O(n) 与最坏 O(n²)**：期望是指随机枢轴下大量运行的平均表现；最坏是运气极差、每轮只丢一个元素的情形。cell1 特意提醒"平均线性不代表每个输入都线性"——每个具体输入的最坏情况仍然存在，只是被随机化稀释了。
- **原地（in-place）与保护输入**：quickselect 直接在传入的数组上换元素（原地、O(1) 额外状态）；`kth_largest` 不想让调用方的数组被搅乱，所以先 `list(nums)` 复制一份再进去，代价 O(n)。

## 三、解决思路（一步步推导）

- **Step 1：确定目标秩。** 对内接口用零基 k（第 k 小）；对外的"第 k 大"先换算成零基 n−k。
- **Step 2：随机选枢轴，三路划分当前窗口 [lo, hi)。** 窗口分成三段：[lo, lt) 全小于枢轴，[lt, gt) 全等于枢轴，[gt, hi) 全大于枢轴。
- **Step 3：看 k 落在哪段。** 若 k < lt，答案在小于段，窗口缩成 [lo, lt)；若 k ≥ gt，答案在大于段，窗口缩成 [gt, hi)；否则 lt ≤ k < gt，k 正落在等值块里，而块里全是枢轴值，直接返回 a[k]（= 枢轴值）。
- **Step 4：重复 Step 2–3**，窗口一轮比一轮小，直到命中等值块返回。

**手算演示：`quickselect([3,2,1,5,6,4], k=4)`（即上面"第 2 大"的内部调用；枢轴由随机数决定，下面取一轮典型值演示，逻辑与随机结果完全一致）。**

第一轮，窗口 [0,6)，假设抽到枢轴值 3。三路划分（过程与 N039 的手算演示同款）得到 [2,1,3,6,4,5]、lt=2、gt=3：a[:2]=[2,1] 全小于 3，a[2:3]=[3] 等于 3，a[3:]=[6,4,5] 全大于 3。检查 k=4：4 < lt=2 不成立；4 ≥ gt=3 成立，说明第 4 小的值在大于段，窗口缩成 [3,6)，小于段 [2,1] 整体丢弃——它们都排在第 4 小前面，永远不用再看。

第二轮，窗口 [3,6)（元素 6,4,5），假设抽到枢轴值 5。划分得 [4,5,6]、lt=4、gt=5：a[3]=4 小于 5，a[4]=5 等于枢轴，a[5]=6 大于 5。检查 k=4：4 < 4 不成立；4 ≥ 5 不成立；于是 4 落在等值块 [4,5) 里，返回 a[4] = **5**。两轮结束，答案与"排序后取 sorted(a)[4]=5"一致，而我们总共只划分了 6+3 = 9 个元素，远少于全排序的工作量。

**cell6 的对照表**把两种秩的换算全部列了出来（a=[3,2,1,5,6,4]，n=6）：

| 第k大（1基） | 对应零基小秩 n−k | 答案 |
|---|---|---|
| 1 | 5 | 6 |
| 2 | 4 | 5 |
| 3 | 3 | 4 |
| 4 | 2 | 3 |
| 5 | 1 | 2 |
| 6 | 0 | 1 |

你可以拿任一行用"排序后数下标"验证，比如第 4 大 = 零基第 2 小 = sorted(a)[2] = 3。

顺带用第 4 行体会一下"第 k 小"这个身份的含义：值 3 恰好把数组分成两个更小的（1、2）和两个更大的（4、5）——第 k 小的值天然满足"左边恰有 k 个元素不超过它、右边都是不小于它的"，这正是第五节"丢掉一侧安全"的直观版本：划分后我们只是把这句话变成了可以机器执行的比较。

## 四、代码逐段讲解

### 函数 1：`quickselect` —— 零基第 k 小

```python
def quickselect(a,k,rng):
    if not 0<=k<len(a): raise ValueError('k must be a valid zero-based rank')
    lo,hi=0,len(a)
    while True:
        pivot=a[rng.randrange(lo,hi)]; lt=i=lo; gt=hi
        while i<gt:
            if a[i]<pivot: a[lt],a[i]=a[i],a[lt]; lt+=1; i+=1
            elif a[i]>pivot: gt-=1; a[i],a[gt]=a[gt],a[i]
            else: i+=1
        if k<lt: hi=lt
        elif k>=gt: lo=gt
        else: return a[k]
```

- `if not 0<=k<len(a): raise ValueError(...)`：入口守卫。零基合法秩是 0..len(a)-1，k 越界（负数或 ≥ n）直接报错；链式比较一行查两头。
- `lo,hi=0,len(a)`：当前搜索窗口 [lo, hi)，从整个数组开始。注意与快排不同，这里**不再压栈另一侧**，窗口只会单向收缩。
- `while True:`：主循环。因为每轮窗口必然严格缩小（见第五节），循环一定终止，用 while True 顶层的写法省掉循环条件。
- `pivot=a[rng.randrange(lo,hi)]`：从窗口里随机取一个下标、拿它的值当枢轴（这里不需要换到开头，因为我们只用 pivot 这个值，不用它的位置）。
- 内层 `while i<gt:` 三分支：与 N039 的 partition3 逐字同款的三路划分。小于分支交换后 lt、i 双前进；大于分支 gt 先减再交换、**i 原地不动**（换回来的元素未分类，要再审）；等于分支 i 前进。
- `if k<lt: hi=lt`：目标在小于段，窗口右边界收到 lt，大于段和等值块整体丢弃。
- `elif k>=gt: lo=gt`：目标在大于段，窗口左边界推到 gt，小于段和等值块整体丢弃。
- `else: return a[k]`：lt ≤ k < gt，k 落在等值块里，块内所有位置上都是枢轴值，a[k] 即答案。

三个出口一张速查表：

| 分支条件 | 含义 | 动作 |
|---|---|---|
| k < lt | 第 k 小在小于段 | hi=lt，右侧两段整体丢弃 |
| k >= gt | 第 k 小在大于段 | lo=gt，左侧两段整体丢弃 |
| lt ≤ k < gt | 第 k 小就是枢轴值 | return a[k]，当场收工 |

### 函数 2：`kth_largest` —— 对外的"第 k 大"

```python
def kth_largest(nums,k):
    if not 1<=k<=len(nums): raise ValueError('k is one-based')
    return quickselect(list(nums),len(nums)-k,Random(41))
```

- `if not 1<=k<=len(nums): raise ValueError('k is one-based')`：1 基合法性检查——k 从 1 到 n，写明约定防止调用方误传零基。
- `quickselect(list(nums),...)`：传 `list(nums)` 复制品，因为 quickselect 会原地打乱数组；复制是保护调用方输入的礼貌，代价 O(n)。
- `len(nums)-k`：秩换算——第 k 大（1 基）等于零基第 n−k 小。n=6、k=2 → 4，对应第三节手算。
- `Random(41)`：固定种子的随机源，让函数每次运行的行为可复现（测试友好）。

## 五、为什么是对的？复杂度是多少？（说人话）

**为什么丢掉的那一侧是安全的？** 我们把每轮的三个分支说成完整的话。划分之后，小于段里的每个元素都严格小于枢轴，等值块里的元素都等于枢轴，大于段里的元素都严格大于枢轴——而且这三段在"排好序的数组"里的位置正是从左到右依次排开的：小于段占据最终秩 lo..lt-1，等值块占据 lt..gt-1，大于段占据 gt..hi-1。于是：当 k < lt 时，第 k 小必然在小于段里（它比小于段里所有元素还要靠前，绝不可能在等值块或大于段），丢掉另外两段不亏一个答案；当 k ≥ gt 时同理，答案只能在大于段；当 lt ≤ k < gt 时，最终排在下标 k 的元素就是等值块的一员，块里全是枢轴值，直接返回。无论哪个分支，"当前窗口永远包含零基第 k 小的那个元素"这条性质每轮都保持。

**为什么循环一定停？** 每一轮，枢轴值取自当前窗口，所以等值块至少含一个元素，lt < gt 严格成立。三个分支里，前两个把窗口长度从 (hi-lo) 缩到不超过 (gt-lt) 与两侧长度之和的较小一侧——不管哪种情况，新窗口都比旧窗口至少少掉整个等值块（≥1 个元素），长度严格下降；第三种情况直接返回。长度是自然数又严格下降，循环轮数有限，必然终止。

**复杂度是多少？** 期望视角：随机枢轴下，每轮窗口期望缩到原来的一个比例（哪怕按"每轮只丢掉十分之一"这种保守估计），总工作量也是 n + 0.9n + 0.81n + … 收敛到 O(n) 量级；常引用的直觉是理想对半分时 n + n/2 + n/4 + … ≈ 2n。拿数字感受：n = 10⁵ 时期望约二三十万次操作，比全排序的约 170 万次快近一个量级；但最坏情形（每轮枢轴都恰好把窗口只削掉一个元素）仍要 1+2+…+n ≈ n²/2 次，n = 10⁵ 就是五十亿次——随机化的意义是让这种倒霉序列几乎不可能被抽中。空间上：quickselect 原地、只有几个指针变量 O(1)；kth_largest 为保护输入复制整个列表，O(n)。

把三种"取第 k 个"的办法放到同一张表上比（用 n=10⁵ 给量感）：

| 办法 | 时间 | 空间 | 附注 |
|---|---|---|---|
| 全排序后取下标 | O(n log n) ≈ 170 万次 | 归并 O(n) 或原地快排 O(1) | 干得多、拿得少 |
| 快速选择（本章） | 期望 O(n) ≈ 二三十万次 | O(1) | 最坏 O(n²)，随机化把坏运气稀释 |
| 大小为 k 的小顶堆 | O(n log k) | O(k) | k 很小时极划算；k≈n 时退回 n log n |

cell1 那句"平均线性不代表每个输入都线性"对着表中间一行读：期望是"随机枢轴下多次运行的平均"，具体某一次运气差仍可能接近最坏列——所以刷题时若输入可能被构造（或要求最坏保证），得换中位数枢轴或堆解。

## 六、测试用例在测什么

cell8 的断言逐条看：

- `assert kth_largest([3,2,1,5,6,4],2)==5`：**正常值测试（手算锚点）**。LeetCode 215 的示例输入，第 2 大是 5，第一节已手推；它同时验证了"1 基转零基"的换算没有搞反方向（若错写成 k−1，会返回第 4 小 = 3，当场露馅）。
- 随机块（`rng=Random(11)`，n 从 1 到 59，值取 −4..4，对每个 n 的数组**遍历所有 k**）：**交叉验证测试（暴力当裁判 + 全秩覆盖）**。断言 `quickselect(a[:],k,rng)==sorted(a)[k]`——排序后取下标 k 就是零基第 k 小的标准答案。值域只有 9 种保证大量重复元素，专测三路划分的等值块分支（无重复时等值块分支几乎走不到）；`a[:]` 复制是因为 quickselect 原地打乱，不复制会让后续 k 的断言用脏数组。注意这里同一个 rng 被反复使用，随机序列持续演进，覆盖了各种枢轴运气。
- `assert kth_largest([7]*100,100)==7`：**极端值测试（全相等 + k 取满 n）**。100 个 7、第 100 大：第一轮划分等值块就吞下全部 100 个元素，k=99 落在块内直接返回。它同时测了 k 的上边界（k=n 合法）和"等值块一步命中"的快速路径——朴素二路选择在这类输入上会一层层剥，三路版一轮收工。

| 断言 | 类型 | 它防的是哪类 bug |
|---|---|---|
| kth_largest([3,2,1,5,6,4],2)==5 | 正常值（手算锚点） | 1 基/零基换算方向搞反 |
| 随机数组遍历全部 k 对拍 sorted(a)[k] | 交叉验证（全秩 + 重复值） | 等值块分支走错、秩偏一 |
| kth_largest([7]*100,100)==7 | 极端值（全相等 + k=n） | k 上边界、等值块命中失效 |

## 七、练习思路提示

- **练习 1（用堆给出另一解并比较 K 的影响）**：方向提示——维护一个大小为 k 的**小顶堆**：先塞前 k 个元素，之后每个新元素与堆顶（当前第 k 大）比较，更大就弹堆顶、压新元素；扫完数组堆顶就是第 k 大，代价 O(n log k)。然后做对比实验：k 很小（如 k=2，n=10⁵）时堆解约 2×10⁵×log2 次操作、还只扫一遍数组，非常划算；k ≈ n/2 时 log k ≈ 17，堆解接近 170 万次，与快速选择的期望二三十万次拉开差距。把"K 的大小如何决定选堆还是选选择"写成结论，并用两个具体 k 实测计时。
- **练习 2（保留输入的非原地接口）**：方向提示——quickselect 会打乱数组，这对外部调用是副作用。改法很直白：函数入口 `a=list(a)` 复制一份再跑（kth_largest 已经这么做了）。要写清的点：复制代价 O(n) 是否可接受、有没有"既不复制又能保输入"的办法（比如返回前把数组复原——但复原本身要 O(n) 且需要额外信息，得不偿失）；边界测一个两元素数组验证原数组在调用后纹丝不动。

两道练完的自查标准：你能对着别人讲清"为什么快速选择敢丢一侧"（第五节第一段的秩区间论证），以及"为什么 kth_largest 非复制不可"，就算过关。
