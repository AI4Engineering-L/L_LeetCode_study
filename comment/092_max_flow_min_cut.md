# N092 · 网络流、最小割与匹配归约 —— 说人话详解

> 对应 notebook：`notebooks/11_graphs/092_max_flow_min_cut.ipynb`

## 一、这章要解决什么问题？（问题描述）

想象一张自来水管网：水从水厂（源点 source）出发，经过一堆管道，最后流到用户家（汇点 sink）。每根管道有一个容量上限（capacity），比如某根管子一分钟最多过 3 升水。我们要回答的问题是：**从水厂到用户家，一分钟最多能送多少水？** 这就是最大流问题。

这个问题受两类限制约束：一是每根管子不能超过容量；二是中途每个路口（既不是源也不是汇的点）流进来多少就必须流出去多少，不能在中途凭空囤水或造水，这就是"流守恒"。

给你一个具体到数字的例子（就是 notebook cell6 里那个小网络）：4 个点编号 0~3，五条有向边：0→1 容量 3、0→2 容量 2、1→2 容量 1、1→3 容量 2、2→3 容量 3。我们从 0 送水到 3，答案是 **最大流 = 5**。为什么是 5？你看点 0：它只有两条出边，容量 3+2=5，所以无论怎么流，从 0 出去的流量不可能超过 5；而 5 恰好能送到（0→1 送 3，其中 2 直接走 1→3，另 1 走 1→2→3；0→2 送 2 走 2→3）。所以瓶颈就是把点 0 "圈出来"的那一刀，这一刀就叫**最小割**，源侧集合就是 {0}。

本章还做一件事：把"二分图最大匹配"这个问题翻译成最大流问题来解（叫"归约"），后面细讲。

## 二、关键概念（定义）

- **容量（capacity）**：每条边允许通过的最大流量，本章只允许非负整数。负容量没有物理意义，代码里会直接报错。
- **流（flow）**：每条边上实际分配的量，必须满足 0 ≤ 流量 ≤ 容量。
- **流守恒**：对每个中间点，流入总量等于流出总量。水不会在半路消失，也不会凭空冒出来。
- **残量网络（residual network）**：在当前流量的基础上，"还能再塞多少"的图。一条容量 3、已用 2 的边，残量是 1，意思是还能再压 1 单位过去。
- **反向边（reverse edge）**：每条正向边旁边自动配一条容量 0 的反向边。它的作用是"后悔药"：如果之前的路径选得不好，后面的流可以推着反向边把已经分配的流量**撤销**一部分、改道走。注意这不是原图真的多了一条运输路线，而是账本上的可撤销额度。
- **层次图（level graph）**：从源点做一次 BFS，给每个点标一个"距离源点几步"的层数。Dinic 只允许流沿着"层数恰好 +1"的边走，这样每次找路径都是最短路，不会绕圈。
- **阻塞流（blocking flow）**：在当前层次图里，往死里送流，直到源到汇的每条路径上都至少有一条边被塞满（饱和），再也送不动为止。
- **当前弧（current arc）**：一个"记事本"指针。它记下每个点已经试过且证明没用的边，下次到这个点直接从记事本位置继续，不用把死边重新扫一遍。
- **割（cut）**：把所有点切成两堆，源在一堆、汇在另一堆。割的容量 = 所有从源侧跨到汇侧的边的容量之和。你可以理解为"一刀剪断哪些管子，水就断了"。
- **最大流最小割定理**：最大流的数值一定等于最小割的容量。这句话同时给了我们一个验证工具：算完流之后，用割的容量来核对答案是不是真的最优。
- **二分匹配归约（matching via flow）**：左边一排人、右边一排座位，每人只愿意坐某些座位，问最多几个人同时有座位。我们把它改造成流网络：加一个超级源连每个人（容量 1），人连他愿意的座位（容量 1），座位连超级汇（容量 1），跑最大流，流量就是匹配数。

## 三、解决思路（一步步推导）

Dinic 算法的整体循环是这样的：

1. **Step 1：建层次图。** 从源点 BFS，只走残量大于 0 的边，给每个可达点标层数。如果汇点标不上层数（根本到不了），说明送完了，算法结束。
2. **Step 2：在层次图里发阻塞流。** 沿着"层数 +1"的边 DFS 找一条源到汇的路径，路径上所有边里残量最小值就是这条路的瓶颈，把瓶颈大小的流量压过去（每条边扣掉相应残量，反向边加上相应容量）。
3. **Step 3：重复 Step 2**，直到当前层次图里再也找不到能走的路径，就回到 Step 1 重建层次图。
4. **Step 4：输出总流量；顺便用 BFS 求出源点的可达集，它就是最小割的源侧。**

下面我们把 cell6 的小网络一轮一轮手算出来。网络：0→1(3)、0→2(2)、1→2(1)、1→3(2)、2→3(3)，源 0 汇 3。

**第一轮：BFS 建层次图。** 从 0 出发：level[0]=0；扫 0 的出边 0→1（残量 3>0）、0→2（残量 2>0），得 level[1]=1、level[2]=1；再扫 1 和 2 的出边，得 level[3]=2。汇点有层数，继续。

**发流（沿层数 +1 的边）：**
- 第一条路 0→1→3：瓶颈 = min(3, 2) = 2。执行后 0→1 残量 1、1→3 残量 0（饱和）。
- 第二条路 0→1→2→3：瓶颈 = min(1, 1, 3) = 1。执行后 0→1 残量 0（饱和）、1→2 残量 0、2→3 残量 2。
- 第三条路 0→2→3：瓶颈 = min(2, 2) = 2。执行后 0→2 残量 0、2→3 残量 0（饱和）。
- 现在 0 的两条出边全饱和，第一轮阻塞流共送出 2+1+2 = 5。

**第二轮：再做 BFS。** 0 的出边残量全是 0，BFS 连点 1、2 都到不了，level[3] = -1，算法结束，总流量 = 5。最后再 BFS 一次，可达集只有 {0}，这正是最小割源侧；跨割的边 0→1(3) 和 0→2(2) 容量和 = 5 = 最大流，验证通过。

运行 cell6 后你会看到输出 `最大流 5 源侧最小割 {0}`，以及一张每条边的容量/流量表：

| 起点 | 终点 | 容量 | 流量 |
|---|---|---|---|
| 0 | 1 | 3 | 3 |
| 0 | 2 | 2 | 2 |
| 1 | 2 | 1 | 1 |
| 1 | 3 | 2 | 2 |
| 2 | 3 | 3 | 3 |

你可以逐行核对：每行流量都不超过容量；点 1 流入 3、流出 2+1=3，守恒；点 2 流入 1+2=3、流出 3，也守恒。

## 四、代码逐段讲解

cell3 的实现全部塞在一个 `Dinic` 类加一个归约函数里，我们逐个看。

**1. 构造函数：**

```python
def __init__(self,n): self.adj=[[] for _ in range(n)]; self.original=[]
```

`adj[v]` 是点 v 的邻接边表，每条边存成三元组 `[对面点, 反向边在对面邻接表里的下标, 残量]`。`original` 记住每条边最初加进来时的样子（在哪个点的边表、下标几、原始容量），最后算"实际流量"时要用它来对账。

**2. 加边：**

```python
def add_edge(self,u,v,capacity):
    if capacity<0: raise ValueError('nonnegative capacity required')
    i,j=len(self.adj[u]),len(self.adj[v])
    self.adj[u].append([v,j+(u==v),capacity])
    self.adj[v].append([u,i,0]); self.original.append((u,i,capacity))
```

`if capacity<0` 这行是在挡非法输入：容量是物理上限，负数没有意义，直接抛异常。`i`、`j` 分别是这条正向边、反向边即将落的位置。正向边 `[v, j+(u==v), capacity]` 的第二个字段是它的反向边下标；当 u==v（自环）时正向边和反向边落在同一个列表里，先 append 的正向边在下标 i，后 append 的反向边在下标 i+1，所以要用 `j+(u==v)`（True 当 1 用）修正下标。反向边初始残量是 0，表示一开始没有任何可撤销的流量。注意 `self.adj[u]` 与 `self.adj[v]` 是同一个列表时（自环），i 和 j 都取自 append 之前的长度，这样正向边记 j+1、反向边记 i，正好互指。这种写法天然支持平行边（两条 u→v 互不干扰）和自环。

**3. BFS 建层次图：**

```python
def _levels(self,s):
    level=[-1]*len(self.adj); level[s]=0; q=deque([s])
    while q:
        u=q.popleft()
        for v,rev,cap in self.adj[u]:
            if cap>0 and level[v]==-1: level[v]=level[u]+1; q.append(v)
    return level
```

`level` 初始化全 -1 表示"还没被 BFS 碰到"。`cap>0` 这个条件很关键：残量为 0 的边等于不存在，BFS 不能踩它。这个函数后面还被复用来找最小割可达集。

**4. 用显式栈发一条增广路径（代替递归 DFS）：**

```python
def _send_one(self,s,t,level,ptr):
    vertices=[s]; path=[]; bottleneck=[float('inf')]
    while vertices:
        u=vertices[-1]
        if u==t:
            amount=bottleneck[-1]
            for a,i in path:
                edge=self.adj[a][i]; edge[2]-=amount
                self.adj[edge[0]][edge[1]][2]+=amount
            return amount
        while ptr[u]<len(self.adj[u]):
            v,rev,cap=self.adj[u][ptr[u]]
            if cap>0 and level[v]==level[u]+1: break
            ptr[u]+=1
        if ptr[u]==len(self.adj[u]):
            vertices.pop(); bottleneck.pop()
            if path: parent,_=path.pop(); ptr[parent]+=1
        else:
            i=ptr[u]; v,rev,cap=self.adj[u][i]
            path.append((u,i)); vertices.append(v); bottleneck.append(min(bottleneck[-1],cap))
    return 0
```

三个栈同步走：`vertices` 是当前走过的点、`path` 是当前路径用的边（存"哪个点的第几条边"）、`bottleneck` 是走到当前位置为止的最小残量。走到汇点 t 时，`bottleneck[-1]` 就是这条路能塞的量；回填时对路径上每条边 `edge[2]-=amount` 扣残量，同时 `self.adj[edge[0]][edge[1]][2]+=amount` 给它的反向边加等量"可撤销额度"。中间那个内层 `while ptr[u]...` 是当前弧优化：从上次停的位置接着找第一条"残量>0 且层数恰好+1"的边；如果扫到头了（`ptr[u]==len(...)`）说明这个点在此层次图里是死路，退栈回溯，并把父结点的当前弧 `+=1` 跳过那条通往死路的边——这就是"不要反复扫描已无用的边"。整个函数要么返回一条路径的流量，要么返回 0（阻塞流完成）。

**5. 主循环：**

```python
def max_flow(self,source,sink):
    if source==sink: raise ValueError('source and sink must differ')
    total=0
    while True:
        level=self._levels(source)
        if level[sink]==-1: return total
        ptr=[0]*len(self.adj)
        while True:
            amount=self._send_one(source,sink,level,ptr)
            if not amount: break
            total+=amount
```

`source==sink` 是在挡"自己流向自己"这种没定义的输入。外层循环是"建层次图 → 发阻塞流"，内层循环逐条发路径。`ptr` 在同一张层次图内共用，这就是当前弧记事本能省时间的原因。BFS 到不了汇就返回累计的 `total`。还要注意一个契约：重复调用 `max_flow` 返回的是"在当前残量网络上**新增加**的流量"，所以第二次调用通常返回 0（第一次已经送满了）。

**6. 最小割与对账：**

```python
def min_cut_reachable(self,source):
    return {i for i,d in enumerate(self._levels(source)) if d!=-1}
def edges_with_flow(self):
    return [(u,self.adj[u][i][0],cap,cap-self.adj[u][i][2]) for u,i,cap in self.original]
```

算完最大流后，残量网络上源点能到达的点集就是割的源侧——因为跨出这个集合的正向边全部饱和（否则 BFS 就冲出去了）。`edges_with_flow` 用 `original` 里记的原始容量减去当前残量，得到每条边的实际流量，方便你肉眼检查守恒。模块级的 `min_cut_reachable(network, source)` 只是把方法包装成普通函数。

**7. 二分匹配归约：**

```python
def matching_via_flow(left_adj,right_size):
    left_size=len(left_adj); source=left_size+right_size; sink=source+1; net=Dinic(sink+1)
    for u,a in enumerate(left_adj):
        net.add_edge(source,u,1)
        for v in set(a): net.add_edge(u,left_size+v,1)
    for v in range(right_size): net.add_edge(left_size+v,sink,1)
    return net.max_flow(source,sink)
```

编号方案是：左边点占 0..left_size-1，右边点接在后面，最后两个编号当超级源和超级汇。所有边容量都是 1：一个人只能被匹配一次（源→人 容量 1），一个座位只能坐一个人（座位→汇 容量 1）。`for v in set(a)` 先去重，防止重复邻接把容量悄悄加成 2。这样跑出的最大流数值恰好等于最大匹配数。

## 五、为什么是对的？复杂度是多少？（说人话）

**为什么流总是合法的？** 每次我们只往路径上压"瓶颈"那么多的流量，所以任何边的流量都不会超过容量；而流的进出只在源和汇两端变化，中间点的进出永远一进一出抵消，守恒不会被破坏。反向边让算法具备了"反悔"能力：后面发现的更好走法可以把前面路径上的流量推回去改道，这就是为什么贪心地一条条塞路径最后仍能达到最优。

**为什么结束时就是最大流？** 算法停止的那一刻，BFS 从源点出发在残量网络里到不了汇点。把"到得了的点"记作集合 S（包含源点），"到不了的点"记作集合 T（包含汇点）。任何一条从 S 跨到 T 的正向边，如果还有剩余容量，BFS 就应该能踩着它过去——所以这些边全部是满的；反过来，从 T 跨回 S 的边如果带着流量，它的反向边（在残量网络里从 S 指向 T）就有残量，BFS 也应该能过去——所以这些边的净流量是 0。于是"穿过这一刀的净流量 = 这一刀的容量总和 = 当前总流量"。另一方面，任何可行流想从源到汇，至少要穿过这一刀，所以任何流的数值都不可能超过任何割的容量。我们的流碰到了这个上界，说明它就是最大的，同时这一刀就是最小的割——一个算法同时拿到两个问题的答案和证明。

**复杂度。** Dinic 的标准上界是 O(V²E)（V 是点数、E 是边数）：每个"阶段"（一次层次图 + 阻塞流）最多 V 个（因为汇点的层数每个阶段严格增加，而层数不超过 V），每个阶段内的阻塞流用当前弧 + 逐路径发送是 O(VE)。拿具体数字感受一下：V=100、E=1000 的小网络，上界大约是 100²×1000 = 10⁷ 级别的操作，普通电脑不到一秒就算完；哪怕 V=10⁴、E=10⁵，理论上界很吓人，但实际网络远达不到最坏情形，Dinic 在竞赛里跑得飞快。辅助的 BFS/可达集是 O(V+E)，可以忽略不计。前提方面：容量必须是非负整数（浮点容量会有精度陷阱），本章实现支持平行边和自环。

## 六、测试用例在测什么

cell8 的测试分两块。

**第一块：随机小网络的全面核对（循环 `for n in range(2,7)`，每个规模 25 组）。** 每组随机造 n 个点、12 条边（容量 0~4 随机）的小网络，然后做四件事：

- `assert value==min(cuts)`：暴力枚举所有 2ⁿ 种"源在一边、汇在另一边"的切法，把每一种割的跨边容量和都算出来取最小值，再和 Dinic 算的最大流比对。这是拿"最大流最小割定理"当标尺：如果 Dinic 的流不是最大的，那它必定小于某个割的容量，这个断言就会炸。注意小网络 n≤6 才能这么暴力（2⁶=64 种切法），大规模就没有这种免费标尺了。
- `assert 0<=f<=cap` 加上 balance 三连断言：逐边检查流量不越容量；再用 `balance` 数组累计每个点的净流出，源点应该是 `-value`（净流出等于总流量），汇点是 `+value`，其余点全 0。这检查的是"我们送的东西真的是一个合法的流"。
- `assert sum(...)==value`：用 `min_cut_reachable` 拿到可达集，数一遍从这个集合跨出去的原始边容量，它应该恰好等于流量。这是把"最小割源侧"的性质也验证了一遍。
- `assert net.max_flow(0,n-1)==0`：第二次调用 `max_flow` 应该返回 0，验证"重复调用返回的是新增流量"这个契约——网络已经被第一次调用送满，没有新增可言。

**第二块：匹配归约的两个固定例子。**

- `assert matching_via_flow([[0,1],[0]],2)==2`：左边两个人，人 0 愿意坐座位 0 或 1，人 1 只愿意坐座位 0。最大匹配是 2（人 0 坐 1、人 1 坐 0），这是正常值测试。
- `assert matching_via_flow([[],[]],3)==0`：两个人都不愿意坐任何座位，匹配数当然是 0。这是边界值测试——没有任何可匹配边时结果应为 0 而不是报错。

## 七、练习思路提示

**练习 1（把二分匹配归约为单位容量流）**：思路方向是照着 `matching_via_flow` 的三段式自己写一遍并讲清楚——超级源到每个左点容量 1、左点到它认可的右点容量 1、每个右点到超级汇容量 1。你要写明白输入（左点的邻接列表、右边点数）和输出（一个整数=匹配数）是什么。手算示例建议用 2×2 的小例子，先肉眼看答案，再和接口结果对。边界至少考虑三种：某个人没有候选座位、邻接列表里有重复座位（想一下为什么必须去重）、左边为空。验证时可以再写一个暴力枚举所有配对的笨办法，两边对照。

**练习 2（说明本章是通用拓展而非 1349 必需解法）**：1349 考试座位题的主流解法是按行状态压缩 DP（把每一排的落座情况编码成二进制），而不是网络流。你要做的是把两种思路摆在一起比较：DP 直接枚举行状态；而如果把它建成本章这种"人—座位"的流网络或匹配模型，就能套用 `matching_via_flow` 这类现成工具。练习的关键不是写出新代码，而是说清楚"归约的代价和收益"——什么时候值得把问题翻译成流，什么时候原地 DP 更简单。同样先给一个 3×3 座位的小例子手算，再下结论。
