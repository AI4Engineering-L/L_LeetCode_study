# REWRITE_BRIEF · 云端智能体任务简报：吸收 comment/ 优化 notebooks/

> 本文件是给自动化智能体的改写任务书。配套 commit：`docs: add plain-language companion commentaries for all 175 notebooks`（comment/ 全量 176 文件）。

## 背景

`notebooks/` 下 175 个 notebook（编号 N001–N175）采用固定 12-cell 模板：

| cell | 内容 | 现状问题 |
|---|---|---|
| c00 | `# N0XX · 标题` + 目标/先修/知识点 | 保持不动 |
| c01 | `## 从问题到算法`（唯一推导段） | 高度压缩书面语，4 句话跳到代码，无例子 |
| c02 | `## 最小实现`（接口列表） | 保持不动 |
| c03 | 核心实现代码 | 零注释、紧凑写法（`n<0`、单行 if） |
| c04 | `## 正确性、前提与复杂度` | "互斥且完备/不重不漏/以n归纳"式术语 |
| c05/c06 | 小实例与可视化（show_table） | 保持不动 |
| c07/c08 | 自动测试（assert） | 保持不动（断言值不许改） |
| c09–c11 | 练习 / 代表题 / 自测 | 保持不动 |

学习者反馈："太跳跃、语言解释不清楚"。`comment/NNN_topic.md`（与 notebook 同名）是每个 notebook 的展开讲解，是本次改写的**唯一素材来源**，每份固定 8 节：问题描述（带数字例子）/ 关键概念定义 / 分步推导（带手算演示）/ 代码逐段讲解 / 正确性与复杂度口语版 / 测试逐条解读 / 练习提示 / LeetCode 映射。

## 改写规则（对每个 notebook 执行）

1. **c01**：吸收对应 comment 的第一节 + 第三节，改写为分步推导。必须保留"输入 X → 输出 Y → 为什么"的具体数字例子和至少一个手算演示；句子完整、有主语。
2. **术语**：c01/c04 中术语首次出现处，吸收 comment 第二节的大白话定义当场解释（例："记忆化（把算过的答案存起来，下次直接查，不再重算）"）。
3. **c04**：吸收 comment 第五节，把压缩论证改写为完整口语句子；禁用"互斥且完备、不重不漏、以n归纳、基例"这类术语；复杂度配具体 n 的量级举例（如 n=10⁵ 时 O(n) 约十万次操作）。
4. **c03**：只允许**添加中文注释**（逐段说明在干嘛、紧凑写法的含义），禁止改变代码语义、函数名、接口与断言值。
5. **禁区**：c05–c11 的模板套话、cell 顺序、cell 数量、文件名、编号一律不动；`COURSE_INDEX.md`、目录结构、`comment/` 目录本身一律不改。
6. **验证**：每改完一个 notebook，执行其全部 cell（至少 c08 的 assert）确认通过。
7. **提交**：按模块分批提交，commit message 格式 `rewrite: N0XX absorb comment/NNN_topic`。

## 验收标准

- [ ] 175 个 notebook 的 c01/c04 语言平实、有具体数字例子，术语有当场解释
- [ ] c03 代码含逐段中文注释且行为不变
- [ ] 全部 assert 通过（Restart and Run All 语义）
- [ ] cell 数量与顺序、文件名、COURSE_INDEX.md、comment/ 均未改变
- [ ] 提交按模块分批，格式符合第 7 条
