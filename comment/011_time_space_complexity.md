# N011 · 时间与空间复杂度 —— 说人话详解

> 对应 notebook：`notebooks/01_reasoning/011_time_space_complexity.ipynb`

## 一、这章要解决什么问题？（问题描述）

这一章要解决的问题是：**不实际跑计时，就能预判"输入变大时，我的算法会慢得多快、吃内存多吃得多快"。** 复杂度描述的是操作数随输入规模增长的趋势，不是在某台机器上测出来的一组毫秒数——毫秒数换台电脑就变了，增长趋势不会变。

载体是最经典的 **Two Sum（两数之和）暴力解法**：给一个数组 nums 和目标值 target，找出两个**位置不同**的数，使它们的和等于 target，返回这两个位置。

给你一个具体到数字的例子：

- 输入：`nums = [2, 7, 11, 15]`，`target = 9`
- 输出：`[0, 1]`
- 为什么是它？因为 `nums[0] + nums[1] = 2 + 7 = 9`，恰好等于目标值，而且这是按"从左到右、外层先固定 i、内层扫 j"的顺序找到的第一对。暴力法就是把所有两两组合挨个试，试到就返回。

本章还配了一个"操作数计数器" `count_pair_checks(n)`，专门用来回答"n 个数一共要试多少对"，从而把"算法有多慢"变成一个能算出来的数。

## 二、关键概念（定义）

- **渐进上界（big-O）**：描述"当 n 足够大时，操作数最多按什么速度增长"的记号。O(n²) 的意思是操作数随 n 的平方增长——n 翻倍，时间大约变四倍；n 变十倍，时间变一百倍。我们用它是因为它剔除了机器快慢、常数系数这些无关紧要的细节，只留"增长趋势"这个本质。
- **最坏情况 / 平均情况**：同一个算法在不同输入上的耗时可能不同。最坏情况是"所有输入里最折磨你的那个"所用的时间，平均情况是随机输入下期望的时间。工程保证和刷题时通常先看最坏情况，因为它承诺了"再差也不会差过这条线"。
- **无序对（i < j 的组合）**：从 n 个位置里挑两个、不分先后顺序的选法。Two Sum 里 (i,j) 和 (j,i) 是同一对，规定只按小的在前（i<j）枚举一次。
- **递归栈（recursion stack）**：递归函数一层层调用自己时，系统为每一层保存的局部信息占用的内存。本章知识点提到它：分析空间复杂度时，递归深度也是要算进去的"额外空间"，本章代码没有递归，但概念要知道。
- **输出空间 vs 辅助空间**：输出本身（比如返回的长度为 2 的答案数组）一般不计入"额外空间"；辅助空间指算法为了干活额外申请的内存（变量、临时列表等），复杂度分析重点看后者。
- **位复杂度提醒**：如果数值本身非常大（比如几百位的大整数），一次加法就不是"一次操作"能完成的了，要按位数重新估计。本章两个数相加是小数值，暂不展开，但 cell0 知识点专门提醒了这个坑。
- **完备且不重复（大白话版）**：枚举方案要满足两条——该试的一对不漏（每个可能的答案都会被试到），同一对不试两遍（不浪费）。本章双循环用 `j` 从 `i+1` 开始同时做到了这两点。

## 三、解决思路（一步步推导）

- **Step 1：想清楚要枚举什么。** Two Sum 要找的是"两个不同位置的数"，所以枚举对象是**位置对** (i, j)，其中 i 和 j 不相等。
- **Step 2：约定枚举顺序，避免重复。** 规定永远让 i < j。任何一对不同的位置，把小的排前面后写法是唯一的，所以 (0,1) 和 (1,0) 只会按 (0,1) 被枚举一次——不重复；同时任何满足 i<j 的对都会被枚举到——不遗漏。
- **Step 3：外层 i 从 0 到 n−1，内层 j 从 i+1 到 n−1。** 这样内层的长度依次是 n−1、n−2、…、1、0（i 到最后一个时内层已经空了）。
- **Step 4：数一数总共试了多少对。** 把内层长度加起来：n−1 + n−2 + … + 1 + 0 = n(n−1)/2。notebook 原文用求和式表达：∑(i=0 到 n−1) (n−1−i) = n(n−1)/2。
- **Step 5：对照 n² 得出量级。** n(n−1)/2 = (n² − n)/2，当 n 很大时 n² 占主导，除以 2 和减 n 都只是常数级修正，所以操作数是 O(n²)。这就是"渐进上界"的直观来源。

**手算演示（n = 4，对应数组 [2,7,11,15]）：**

外层 i=0 时，j 走 1,2,3，试三对：(0,1)(0,2)(0,3)；i=1 时，j 走 2,3，试 (1,2)(1,3)；i=2 时，j 走 3，试 (2,3)；i=3 时，j 从 4 出发直接结束，试 0 对。总共 3+2+1+0 = 6 对，公式 4×3/2 = 6，一致。而且第一对 (0,1) 就命中 2+7=9，立刻返回 [0,1]。

把六对全部列出来对照 target=9，你就能看见完整的枚举现场：

| 轮次 | 对 (i,j) | 数值对 | 和 | 与 target=9 比较 |
|------|----------|--------|-----|------------------|
| 1 | (0,1) | 2+7 | 9 | 命中，立即返回 [0,1] |
| （未走到） | (0,2) | 2+11 | 13 | 假设继续会是"不中" |
| （未走到） | (0,3) | 2+15 | 17 | 同上 |
| （未走到） | (1,2) | 7+11 | 18 | 同上 |
| （未走到） | (1,3) | 7+15 | 22 | 同上 |
| （未走到） | (2,3) | 11+15 | 26 | 同上 |

再看无解的小输入 `nums=[1,2]`, `target=8`：只有一对 (0,1)，和为 3≠8，内层走完、外层走完，落到 `return None`——最坏情况下"每一对都白试"，这正是最坏 O(n²) 的来源。

**cell6 表格数据（操作数 vs n² 的增长对比）：**

| n | 无序对次数 n(n−1)/2 | n² |
|---|---------------------|-----|
| 0 | 0 | 0 |
| 1 | 0 | 1 |
| 2 | 1 | 4 |
| 4 | 6 | 16 |
| 8 | 28 | 64 |
| 16 | 120 | 256 |

你观察一下：n 从 8 涨到 16（翻倍），对数从 28 涨到 120（约四倍）——这就是平方增长的手感。

把同一个公式推到刷题常见的规模，账单会更直观（用 `count_pair_checks` 一算即得）：

| n | n(n−1)/2（要试的对数） | 直观耗时 |
|------|------------------------|----------|
| 100 | 4,950 | 瞬间 |
| 1,000 | 499,500 | 瞬间 |
| 10⁵ | 约 5×10⁹ | 数秒，大概率超时 |
| 10⁶ | 约 5×10¹¹ | 基本跑不完 |

结论从表里自己长出来：n 到十万这一档，O(n²) 的暴力法就撑不住了，这不是背表，是算出来的。

## 四、代码逐段讲解

cell3 定义了两个函数。

### 函数 1：`two_sum_bruteforce` —— 暴力枚举所有位置对

```python
def two_sum_bruteforce(nums,target):
    for i in range(len(nums)):
        for j in range(i+1,len(nums)):
            if nums[i]+nums[j]==target:
                return [i,j]
    return None
```

- `for i in range(len(nums)):`：外层枚举第一个位置 i，从 0 到 n−1，逐一固定。
- `for j in range(i+1,len(nums)):`：内层枚举第二个位置 j，从 i+1 开始。这个起点是全函数最关键的一处：它保证 j 永远比 i 大，于是 (0,1) 不会被再按 (1,0) 试第二遍（不重复），同时所有小前大后的对都会走到（不遗漏）。
- `if nums[i]+nums[j]==target: return [i,j]`：判断当前这对的和是不是目标，是就立刻返回两个位置。注意是返回**位置**不是返回数值。
- `return None`：所有对都试完仍没命中，返回 None 表示无解。这也保证调用方能明确区分"找到"和"没找到"。

### 函数 2：`count_pair_checks` —— 直接算出对数

```python
def count_pair_checks(n):
    return n*(n-1)//2
```

- `n*(n-1)//2`：组合数 C(n,2) 的公式，即"从 n 个里挑 2 个、不分顺序"的选法数，也等于第三节数出来的内层长度之和。用整数除法 `//` 保证结果是 int（n(n−1) 必为偶数，所以不会有余数损失）。
- 这个函数的价值是"把 O(n²) 从抽象记号变成具体数字"：想知道 n=16 要试多少对，一乘就知道是 120，不用真跑双循环去数。
- 顺带一提：写 `/2` 也能得到数值，但结果是浮点数，n 大时会丢精度，所以涉及计数的场合一律用 `//`。

## 五、为什么是对的？复杂度是多少？（说人话）

**为什么暴力法一定能找到答案？** 因为任何一对满足条件的不同位置，把小的写在前面后必然形如 i<j；而我们的双循环恰好把所有 i<j 的对每对枚举了一次。所以只要答案存在，它必然在某一轮被 (i,j) 试到并返回；答案不存在时，所有对试完，落到 `return None`。既没有漏网的组合，也没有白试的重复组合。

**为什么提前 return 不影响最坏情况？** 找到就返回确实会让"运气好"的输入（比如答案在前几对就撞上）提前结束，但这只是让某些输入变快。最坏的情况依然存在：答案在最后一对、甚至根本无解，此时所有 n(n−1)/2 对都要试完。复杂度看的是这个"最坏承诺"，所以最坏时间仍是 O(n²)。

**复杂度到底是多少？** 时间：最坏 O(n²)。给你具体数量级感受：n=1000 时约 50 万次比较，一瞬间；n=10⁵ 时约 50 亿次比较，一般要跑好几秒；n=10⁶ 时约 5000 亿次，基本跑不动——这就是为什么刷题看到 n ≤ 10⁵ 的数据范围，你的 O(n²) 解法大概率会超时，得换 O(n log n) 或 O(n) 的思路。空间：辅助空间 O(1)——全程只用了 i、j 两个循环变量，没开任何随 n 增长的结构；返回的答案只有两个数，属于常数大小的输出，按惯例不计入额外空间。

**平均情况呢？** 如果答案对在数组里随机分布，期望大约要试到总对数的一半才命中，也就是仍然与 n² 成正比——只是常数小了一半，量级不变。所以对暴力 Two Sum 来说，看最坏和看平均得到的结论一样：平方级。

## 六、测试用例在测什么

cell8 的每条断言：

- `assert count_pair_checks(0)==count_pair_checks(1)==0`：**边界值测试**。0 个或 1 个元素都无法组成"一对"，公式都应给出 0（0×(−1)/2=0，1×0/2=0），验证公式在最小规模不露馅。
- `for n in range(12): assert count_pair_checks(n)==sum(1 for i in range(n) for j in range(i+1,n))`：**交叉验证测试**。对 n=0 到 11 逐个核对：公式算出的数，是否等于真正跑一遍双循环数出来的对数。生成器表达式 `sum(1 for i ... for j ...)` 就是在模拟双循环逐对计数。公式和实数 12 个规模全部吻合，公式才有说服力。
- `assert two_sum_bruteforce([2,7,11,15],9)==[0,1]`：**正常值测试**。2+7=9 且是枚举顺序下的第一对，应返回 [0,1]，验证"找得到且返回位置"。
- `assert two_sum_bruteforce([1,2],8) is None`：**无解测试**。1+2=3≠8，没有别的对可选，必须返回 None。用 `is None` 判断还能顺带确认返回的确实是 None 对象而不是其他假值。

归档一下，这套测试的挑法本身就是套路：

| 断言 | 类型 | 它防的是哪类 bug |
|------|------|------------------|
| `count_pair_checks(0)==count_pair_checks(1)==0` | 边界值 | 公式在最小规模算出负数/错数 |
| n=0..11 公式 vs 实数双循环 | 交叉验证 | 公式和真实枚举对不上 |
| `[2,7,11,15],9 → [0,1]` | 正常值 | 主逻辑错、返回值而不是位置 |
| `[1,2],8 → None` | 无解 | 找不到时返回错值 |

## 七、练习思路提示

cell9 的两道练习：

- **练习 1（区分 O(n²) 和 O(nm)）**：关键点是看清楚"两个循环各自的规模是不是同一个变量"。双循环都跑同一个数组是 O(n²)；如果外层跑数组 A（长度 n）、内层跑数组 B（长度 m），那就是 O(nm)——当 m 很小（比如 m=3）时它其实接近线性。提示：写一个双循环函数分别枚举两个不同长度的列表，手数 n=3、m=4 时的操作次数（应为 12），再对照 nm 公式；边界情况考虑 m=0。
- **练习 2（分析切片带来的隐藏拷贝）**：Python 的切片 `nums[i:]` 不是"看一眼"，而是**新建一个列表**把元素复制过去，这一步的时间代价和切片长度成正比。提示：想象一个循环里每次都 `nums[1:]`，数一数 n=4 时总共复制了多少个元素（3+2+1=6 个），你会发现表面一层循环 O(n)、实际是 O(n²)；先手数这个小例子，再用 `time` 或操作计数验证。边界情况：空列表和单元素列表的切片各复制几个元素？
