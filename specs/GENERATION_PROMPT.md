# 175章Notebook教程包：生成与验收Prompt

## 输入

读取当前目录的 `curriculum.json`。它是章节编号、文件路径、先修关系和教学规格的唯一权威。`COURSE_CATALOG.md`为阅读视图，`problem_references.json`记录代表题身份核验状态。

本轮章节：由用户指定，例如 `N001–N003`。用户未指定时，从 `learning_order` 中选择先修已完成的最前面1–3章，实际生成、执行和修复，而不是再次生成总计划。复杂章节可单章推进，不以每批固定数量牺牲正确性。

## 目标

把指定章节生成为可独立运行、从问题推导到算法的 `.ipynb`。严格使用记录中的 `path`；不重命名、不新增同义章节，不创建175个空壳后宣称完成。

每章必须落实以下字段：

```text
teaching_goal
knowledge_points
representative_problems
required_code
visualization
exercises
unit_tests
```

检查 `prerequisites`。`optional_code` 与 `optional_prerequisites`只影响拓展部分，不阻塞该章核心交付。需要补先修时，仅生成确实缺失的先修，不临时扩展课程体系。

## 一、核对问题与边界

对本轮真正讲解的代表题读取官方题面，核对题号、标题、输入输出、约束、原地要求、开闭区间、返回顺序、目标语言和可访问性。原清单中 `verify_before_generation` 不是已经核验。

题目角色不可混淆：`canonical`典型题；`warmup`基础热身；`preview`只作预告；`comparison`复用比较；`extension`高级替代或迁移。不声称高级方法是该题必需或最优解法。收费题不能访问时，报告限制，保留官方引用，并以自编同概念练习支撑教学，不猜测未见题面。

若发现目录规格或示例有错，先用官方约束或独立参照定位问题，再最小修正。不要为了让测试通过篡改预期结果。课程自编扩展输入和官方合法输入必须分开标注。

## 二、教学结构

建议按以下教学链组织，不机械堆砌24个空标题：

```text
目标与先修
→ 最小问题及手算
→ 直接解法
→ 重复计算或结构瓶颈
→ 关键性质与推导
→ 最小实现
→ 正确性与复杂度
→ 真实状态可视化
→ 代表题应用与变体
→ 练习、测试、总结
```

中文讲解，代码使用清楚的英文标识符。公式用 `$$ ... $$`，可复制到Obsidian。注释解释状态、不变量、边界和关键取舍，不逐行复述语法。

基础语法章不强行安排Hard题或形式化定理。算法章须明确状态/不变量、适用条件、正确性理由、时间和辅助空间。区分最坏、平均、均摊、位复杂度与输出规模；不能靠一张耗时图证明复杂度。贪心和高级DP优化必须给出相应论证，不能写“显然最优”代替关键步骤。

一个Notebook中可以有多个递进小节。先完成 `required_code`，再决定是否做 `optional_code`。不要把所有代表题都机械扩展成重复长题解。

## 三、实现与独立运行

每个Notebook从空内核可以顺序运行。需要的导入、最小节点定义、教学数据和辅助函数在本章可获得；核心算法必须在正文可见，不藏入不透明工具模块。

优先标准库。图形按需使用Matplotlib，表格也可以直接输出文本。Pandas仅在相应分支作为依赖。不得使用大而全算法框架代写本章需要教学的算法。禁止静默降级、`except: pass`、失败后返回伪造答案、用库函数冒充要求手写的核心算法。

教学代码应短而可读；类型标注和输入验证服务于契约，不为所有输入增加无关兜底。浅层递归用于解释，题目可能有深树/深图时明确递归限制并提供适当迭代路径，不能单纯无限提高递归深度。

Notebook元数据中记录：

```json
{
  "course": {
    "id": "Nxxx",
    "spec_version": "1.0",
    "prerequisites": [],
    "runtime": {}
  }
}
```

## 四、可视化

图表必须由本章代码的真实状态或明确的手算数据生成，显示输入、当前状态、变化及答案之间的关系。优先选择状态表、指针快照、递归树、DP表或队列轨迹，不为了动画引入额外前端依赖。

要求：标签可读；图中数字与代码输出一致；小示例能手工复核；无网络依赖；不要显示数千个节点或打印全部指数状态。图像装饰不能代替算法解释。

## 五、练习与答案

按 `exercises` 提供理解、改错、变体或迁移练习。每项练习明确输入、输出、约束和完成标准。正式结业用未展示过参考解的自编变体，不把课堂原题重做当作陌生题证据。

练习待答区可定义未调用的函数骨架或使用Markdown，不让未完成练习导致教学区Run All失败。参考答案可以放在Notebook末尾的折叠区；练习题和答案明确分区，不能用答案替学生填好所有练习。不要另建175份重复Notebook版本。

## 六、测试

将 `unit_tests` 转成真实断言或测试函数，并在Notebook中执行。至少落实本章指定样例、边界和结构性质；需要时增加独立小规模暴力参照及固定随机源对拍。

验收不只比较打印内容：

- 多解题检验合法性并规范化集合，不要求任意唯一顺序。
- 链表、树和缓存检查身份、引用、无环、恢复及结构不变量。
- 随机算法以等概率推导、可控随机源和小域枚举为主；分布图仅作诊断。
- 性能测试按规模和操作计数设计；暴力参照只跑小输入。不使用脆弱的固定毫秒门槛。

测试不等于正确性证明；规格中的测试尚未执行，不可原样继承“通过”结论。不得将未运行测试标为passed。

## 七、特殊分支执行

**SQL：** Python内核中使用 `sqlite3` 内存数据库创建小表并运行实际SQL。MySQL/其他官方方言单独列出并说明差异；未在该数据库执行就标为未测。测试覆盖NULL、重复键、并列排名、日期缺口、分母和输出顺序。

**Pandas：** 使用真实DataFrame，并用 `pandas.testing.assert_frame_equal` 检查值、列、dtype和按题意规范化后的索引；不能只看截图。

**Shell：** 用真实 `bash/awk/sed/grep/sort/uniq` 处理临时文件，检查退出码与stdout，显式固定影响排序的locale。禁止改成Python解法后声称Shell通过。

**JavaScript：** 使用Python内核组织文档，通过明确的Node.js子进程执行JS脚本与Node断言。各脚本自包含；不要依赖上一个子进程的变量。缺Node时记录环境阻塞，不用Python模拟JS后冒充执行结果。异步测试检查顺序、并发上限、异常传播和资源清理。

**并发：** 用真实线程及同步原语，不用sleep充当同步。可能挂起的演示和压力测试必须在可终止子进程中，设置合理超时并清理。超时即失败；有限压测不证明无死锁或无饥饿。说明公平调度与有限持锁等活性前提。

## 八、执行与修复

用 `nbformat.validate` 检查格式，再用 `nbclient` 或等价Jupyter执行机制从空内核运行，`allow_errors=False`。以Notebook所在目录为工作目录或明确统一资源根。记录实际Python、必要依赖和外部运行时版本，不凭空填写“最新版本”。

修复执行错误后重新执行该Notebook，确认输出与文本一致。检查渲染：公式可读、代码完整、图不裁切、表不溢出、练习与答案分区清楚。不能只做JSON格式验证就宣布教程完成。

一章因外部运行时缺失受阻时，明确记录阻塞，继续同批可独立完成的其他章节；不要重生成已验证完成的章节。

## 九、输出

只交付本轮实际产生的文件和证据：

```text
Notebook ID / 固定路径
本轮完成的核心知识与实现
题面核验情况
格式验证结果
空内核执行结果
测试结果
拓展未完成项或环境阻塞
下一章及其先修
```

更新单一生成状态记录即可，不增加多套manifest、签名、receipt或重复报告。不要把文件数、标题数、空Notebook数当学习内容进展。

完成定义：指定核心实现、解释、可视化和测试真实存在；Notebook空内核运行通过；题意、算法、代码与结果一致。
